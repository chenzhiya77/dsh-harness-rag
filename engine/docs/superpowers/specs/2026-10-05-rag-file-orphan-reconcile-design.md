# RAG 清扫轮盲区收口（文件侧对账 + 已删库/卡片残留）—— 设计

**Status:** ✅ 全交付（2026-10-05）：D1–D6 全甲；Task 0–5 完成，真栈 17/17，门禁 1561/4/2（4=既有环境红）。

**本对一件事：把清扫轮的盲区收干净。** 原三刀在文件侧：把 §5.3 条目 3 的"文件保存、记录创建和任务入队之间的中断也须纳入恢复"补完——现状只有"行→入队"半段被 `worker.recover()` 覆盖；**"文件→行"半段没有兜底**（`create_document` 异常路径与进程崩溃都会把已写文件甩下，且目录级没有任何回收）。2026-10-05 并入两刀向量侧：**①已删库的残留**——`delete_kb_cascade` 的 `delete_by_kb` 失败仅记日志（`knowledge_service.py:570-572`），而清扫轮只枚举 `list_all_kbs()` ⇒ 已删库的点不在扫描面内、没有回收通道；**②卡片关开关失败的残留点**——`update_manual_card` 关闭时删点失败仅记日志（`:1052-1054`），行还在（开关已关），现判据「行存在→保留」（`sweep.py:122`）把残留点永久当非孤儿。2026-10-05 再并入一刀：**③宽度迁移的旧代残留**——迁移收尾删旧代是 best-effort（`rag_migration.py:119-125`），失败后旧代集合不在任何扫描面；它是全族唯一"删错会当场丢服务"的一项，收法要带迁移互斥（§2.6）。四处同族：静默失败留下残留、没有任何回收通道；收法=同一轮 + 同一闸（③另加迁移互斥）。

## 1. 现状与缺口（锚点）

- 上传顺序（`knowledge_service.py:422-441`）：先 `_write()` 落文件（`knowledge/<kb_id>/<doc_id>/<name>`）→ `store.create_document` → `worker.submit`。**create/submit 抛错无补偿**（异常路径即留孤儿目录，触发面比"崩溃窗口"更大）；崩溃在 write 与 insert 之间同理。
- "行→入队"半段：`worker.recover()` 已覆盖（非终态重入队）✓。
- 无回收：没有任何目录级对账；`_remove_dir`（`shutil.rmtree(ignore_errors=True)`）只服务删除链路，**它自己失败（ignore_errors 吞掉）同样留下孤儿目录**（doc 行没了、目录还在——同一族的另一半）。
- 上一对的能力（spec 2026-10-04-rag-orphan-vector-sweep）：清扫轮由 `KnowledgeIndexWorker._sweep_once` 驱动（启动 jitter + `rag.sweep_interval_hours`），闸 = 逐库 busy ∪ wiki 腿、全局迁移；**只碰 Qdrant 点**。
- 向量侧枚举盲区（①）：`_sweep_once` 以 `store.list_all_kbs()` 为枚举源（worker.py）；删库链路 `delete_by_kb` 先于行删除且失败吞掉（`knowledge_service.py:569-573`）⇒ **kb 行没了的点，四个集合里谁也不在扫描面内**。目录侧天然没有这个盲区（walk `knowledge/` 即可覆盖已删库）——同一条准绳的现状两侧不对称，D4 把向量侧补齐。
- 卡片判据缺口（②）：`_sweep_manual_cards` 两段判据均为「行存在」（`sweep.py:122/125`）；关开关失败的残留点（行在、开关关、点陈旧）因此永远保留。影响有上限但真实：查询端 hydration 会跳过禁用卡（`wiki_search_tool.py:59-61`），但 stale 点占据候选池名额，可能把合法卡片挤出 top_k。
- 代次残留（③）：迁移收尾"删旧代"明知 best-effort（`rag_migration.py:119-125`，只 warning）——失败后旧代集合不在任何扫描面（清扫只看当前代的集合名；`init_collections` 只查无后缀 legacy 名）。触发=切换成功后删旧代那一刻 Qdrant 失败；后果=整库向量的一份完整拷贝留在盘上，无 UI 可见性、无重试入口。

## 2. 方案

### 2.1 异常路径即清（同步）

`upload_document` 中 write 之后的任一步失败 → `_remove_dir(doc_dir)` 再抛——覆盖最常见的异常路径；正常成功路径零变化。

### 2.2 目录对账（异步，并入既有清扫轮）

`_sweep_once` 增加一步文件对账（`reconcile_files`）：遍历 `knowledge/` 下 `<kb_id>/<doc_id>` 目录——doc 行不存在（或 kb_id 不匹配）→ 整目录清理（含 `frames/`、`images/`）；`<kb_id>` 目录无 kb 行 → 整棵清理。**walk 判据只认 `<kb_id>/<doc_id>` 形状的目录**；kb 级直挂文件（`golden.jsonl`、`eval_candidates.json`）不属对账面——kb 行在即保留，kb 行无随整棵清（Task 0 实测）。**两段式**：收集候选 → 复核行仍缺 → 再删（覆盖上传 write→insert 在途窗口，与向量清扫同款）。判据=业务行为准绳；幂等；失败仅记录、下轮重试。

### 2.3 触发与并发

随清扫轮同频同闸（复用 `rag.sweep_enabled` / `sweep_interval_hours`；逐库 busy 与迁移闸沿用）。落点需要把 `data_dir` 传入 worker（现只在 `KnowledgeService` 手里）。

### 2.4 向量侧枚举盲区（集合级 pass）

`_sweep_once` 的枚举源从「活库表 × 逐库 scroll」换成**集合级 pass**：每个集合不按 `kb_id` 过滤地扫一遍（`scroll_collection` 支持无过滤或新增 `scroll_all`），按 payload 的 `kb_id` 分组——

- kb 行不存在 → 整组为孤儿（两段式：复核 kb 行仍无 → 按组内 id 调既有 `delete_*` 删）；
- kb 行存在 → 走现判据（逐点查行，不回归）。

扫量与今天相同（所有活库的点都要扫）、调用更少，且对「已删库」自足；`list_all_kbs()` 不再是依赖。**闸语义不收缩**：组内若命中 busy/wiki，整组跳过（与今天"忙库跳过"逐库等价）。

### 2.5 卡片判据升级

`_sweep_manual_cards` 的保留条件改为「行存在**且** `include_in_wiki_search` 为真」——否则进候选；两段复核同理（复核时行仍缺**或**开关仍未开 → 删）。已知残余（登记不另修）：`update_manual_card` 的姿态是 upsert→行写（`knowledge_service.py:1027-1038`，2026-08-16 修过的顺序），开关开启瞬间存在 ms 级窗口（点已写、行仍 False），清扫恰在该窗口复核会误删新点——后果=卡片暂不可检索，再次显式开即自愈（既有路径 `:1023-1024`）。

### 2.6 代次回收（全局一步，带迁移互斥）

清扫轮增加一步**全局代次 GC**（非逐库）：列出 Qdrant 集合，按 `kb_{chunks|entities|wiki_entries|manual_cards}(_\d+)?` 严格匹配，**名字 ≠ 当前生效宽度集合名**的即为残留代，整集合删、逐个吞错（并发删"已不存在"属正常）。锚点=**声明宽度**（`effective_dimension()`，与 `get_vector_store()` 同源），不用 worker 持有的实例。

两道前置（任一不满足即跳过本步）：

- **迁移互斥**：`migration_in_progress()` ∪ 注入的 app 闸 `rag_migration.migration_running`（worker 新构造参数、`app.py` 接线，与 D2 传 `data_dir` 同款）——两闸任一命中整轮跳过。四个交接窗口：

| 窗口 | 谁在服务 | 处置 |
|---|---|---|
| 迁移在建 | 旧代服务、新代在建 | `migration_in_progress()` 覆盖 |
| 建完→翻转前 | 旧代仍服务（配置未翻） | **app 闸覆盖**；无此闸会把新代当残留删掉 ⇒ 翻转折库 |
| 翻转后→删旧代前 | 新代服务 | 旧代可删；与迁移自己的删旧代并发时各自吞错 |
| 崩溃残余（建一半 / 翻后未删） | 配置为准，残余 ≠ 生效代 | 收；与 D5-2「不续跑、直接弃」一致 |

- **生效代在位**：四个生效宽度的集合**全部存在**才动手——防"手改宽度没走迁移"：那时生效代不存在、旧代是唯一副本，GC 必须停手（与 `init_collections` 的 `DimensionMigrationRequired` 是同一状态的两种出口）。

## 4. 硬约束

- 只删文件目录；业务行与 Qdrant 点永不动；判据=业务行存在性（幂等）。
- 与清扫轮同频同闸；**不新增配置面**（复用 `rag.sweep_*`）。
- 上传成功路径零行为变化、不增加额外 IO；失败路径先清再抛。
- 两段式（收集→复核→删）；失败仅记录、下轮重试。
- 向量侧只删两段判据内的点；闸语义逐库精确（集合级 pass 组内跳过忙库，不做全轮收缩）。
- D5 竞态按 §2.5 登记为已知残余，不改 `update_manual_card` 的顺序。
- 代次 GC 只在两道前置（迁移互斥、生效代在位）同时成立时动手；删除逐个吞错、失败下轮重试。

## 5. 验收

1. 单测：`create_document` 抛错 → 请求报错且目录不残留（异常即清）。
2. 单测：孤儿目录（无 doc 行）→ 对账后消失；正常目录/正常库不动；候选复核守护（候选后行出现 → 不删）。
3. 单测：KB 行没了 → 整库目录清理；删除残留目录（`_remove_dir` 吞掉的那类）也被回收。
4. 单测：已删库残留点（kb 行无、四集合有点）→ 整组清；正常库的点不动；忙库组跳过；复核守护（候选后 kb 行出现 → 不删）。
5. 单测：卡片开关关 + 残留点 → 清；开关开 → 保留；复核守护（候选后开关翻回开 → 不删）。
6. 单测：代次 GC——残留代（旧宽度集合组 + 生效代在位）→ 收；生效代不动；建完未翻窗口（app 闸 True）→ 不收；生效代缺失（手改宽度态）→ 不收。
7. 单测：闸命中（忙库/迁移）→ 跳过（两条腿通用）。
8. 门禁：knowledge 面全量 + ruff 双净。
9. 真栈：隔离实例——文件相（"行没了、目录在"+ 上传中途失败一相）+ 向量相（停 Qdrant 后删库与关卡片开关 → 起 Qdrant → 跑一轮）+ 代次相（手造一组残留代集合）→ 目录、残留点与残留代清零、正常库不受影响。

## 6. 非目标

- 不做通用磁盘清理/配额（只回收有键可对账的目录）；
- 不改删除吞错姿态、不回改 §5.3 其他文字（完工后只把条目 3 那半句改写实口径）；
- 不做上传管线重构（顺序与接口不动）；
- 代次 GC 不改变「翻转后谁在用旧代」的既有约定（与迁移收尾同款 best-effort）；worker/service 持有的实例是否随热重载换新属既有行为、不在本对（锚点=声明宽度，Task 0 核实，若陈旧登记另议）；
- 不改 `update_manual_card` 的 upsert→行写顺序（2026-08-16 修过的姿态）。
