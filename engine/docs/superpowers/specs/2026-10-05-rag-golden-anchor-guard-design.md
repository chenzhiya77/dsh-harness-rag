# 题库标注锚定核验门禁 —— 设计

**Status:** 已完工（2026-10-05 收官：Task 0–4 全交付、真栈 B′ 三态过、存量审计 ✓14/✗0/—5、提交链 `b02b51c45`→`cbb8f0578` 9 笔未推）。原裁决：D1=甲′ 拦一次+确认放行 / D2=甲 审计定形口径 / D3=甲 q008 改锚 `#0002→#0001` / D4=甲 `add_question` 单点收口 / D5=零新增常驻控件+B′ 交互）。成对 plan 同名（`../plans/2026-10-05-rag-golden-anchor-guard.md`）。

**本对一件事：给题库出题入库的所有出口加一道「锚定核验」机械门禁——参考答案的术语必须能在标注切片正文里找到，贴错锚在入库那一刻被机器拦下；存量唯一实锤 q008 一并修锚。**

术语约定：**答案锚** = `relevant_chunk_ids` 标注的切片，即"标准答案写在哪几片"；**贴错** = 答案锚指向的切片不含答案内容（答案在别的片里）。

来源：2026-10-05 graph_search 命中率复核翻出的 q008 贴错案（`backend/tests/fixtures/rag_eval/golden.jsonl` 与运行库同错，2026-08-24 seed 批出生即错）；产线现状=人工批与合成批**都没有正文核验**（spec `2026-08-23-rag-retrieval-evaluation-design.md` 冷启动纪律"垃圾题库比没有题库更危险"正是防这类，但无机制兑现）。

## 1. 问题（机制与证据链）

**q008 全链**（单题归因探针实测，2026-10-05）：问题"装箱和拆箱是什么关系？"、参考答案讲互逆转换、答案锚 `#0002`——但 `#0002` **全文 0 次出现"装箱"**（它讲 Integer 缓存池/包装类对比表），真答案在 `#0001`（"什么是自动拆箱/装箱？装箱：将基本数据类型转换为包装类型…"，与参考答案逐句对应）。后果是**双向失真**：graph 腿把 `#0001` 以 rank1 捞出却判 MISS，vector 腿捞到 `#0002`（错片）反判 HIT。

**存量审计实测**（`golden_audit.py` 两库 19 题、零 LLM、14s）：

| 判据版本 | 拦出 | 其中假阳性 |
|---|---|---|
| 无豁免 | 8 | 7（无参考答案 5 + 多片分布 2） |
| **两条豁免后** | **1** | **0**（唯一实锤=q008，建议锚 `#0001` 3/3 vs 1/3） |

⇒ **两条豁免是判据的组成部分，不是边角**：无参考答案的题（5 题）机械核验不适用须跳过；多片锚定题答案术语分散各片，"全集术语比单片"会系统性误判，只拦"单片零命中"级。（口径注：本表是 jieba 术语口径的审计；门禁实跑用二元组口径，对照实测见 §2，两口径判定一致。）

**产线守卫缺口**（两条路都缺同一格）：

1. **人工批**（q001–q019，2026-08-24 seed）：spec 明记"从真实已入库文档人工标注、召回测试面板挑片"——挑片靠主题印象，无正文核对（q008 与 q007 共锚一片本身合理，q007 答案 6/6 在片内，错的只是 q008 的锚）。
2. **合成批**（`eval/synthesis.py`，LLM 按锚点序号指片 + 人审接受）：两道守卫=①锚点界内且整数 ②schema 合法——**都不查正文**；q_ce985656 实证模型看内容能挑对，但没有机制保证。

**为什么门禁在写入口、不在 CI**：切片正文只在运行库（`chunks` 表），git 里的题库 guard 测试只能查 schema 查不了内容；写入口的服务端当场能拿正文。这也是"审计按钮不做 UI"的原因（2026-10-05 已裁：核验是机器自动的，UI 零动作）。

## 2. 方案

**核验函数（单一实现，`deerflow/knowledge/eval/anchor_check.py`）**，五步纯机械、零 LLM、毫秒级：

1. **分词**：复用 `knowledge/sparse.py::_tokenize` 的确定性分词（ASCII 词 as-is + 中文按字二元组）——**不引 jieba**，引 sparse §4.2 先例"index 空间不随环境漂"，且 jieba 只是 `memory-zh` optional extra、进核心会破环境一致性；
2. **抽术语**：参考答案 → 术语/二元组集合 K（ASCII 词保留、中文二元组保留；数字串/单字丢弃）；
3. **查命中**：答案锚正文里查 K 的命中数 h（分词集合交/子串包含，同文档同一把尺）；
4. **找对照**：同文档所有切片算同一命中数，得最佳片 B；
5. **判定**（含两条豁免）：
   - 无参考答案（K 空）⇒ **只免术语核验**（不拦不报），**锚存在性照跑**——空答案题的锚照样进 L1 计分（q017–q019 即是），且两个造题 dialog 的参考答案均可选 ⇒ 空答案**不是**绕过整门禁的通道（审查 ①，2026-10-05）；
   - 多片锚定 ⇒ 只拦"单片命中 0"，被压制只作提示；
   - 单片锚定 ⇒ **h=0 或 B−h ≥ 2 且锚非最佳** ⇒ 拦（贴错级），回显术语命中表 + 建议锚 B；被拦后**人可带一次性确认标记重存入库**（D1=甲′），机器的定位=要求人看一眼，不否决人。阈值在**最终分词口径（二元组）上实测校准**（2026-10-05，14 有答案题 20 锚）：单片 10 锚全 h==B 零误报、q008 h=5/B=8（差 3 ≥ 2 拦）、多片 5 处压制全被豁免 ⇒ **1 拦 0 误杀**，与 jieba 口径审计（§1）判定一致。

**收口（原则钉死，落点 Task 0 核）**：题库**唯一写路径** `question_bank.add_question`（`synthesis.py:16` 注释明记"the single write path"）挂 guard——create（`knowledge_service.py:1543`）与合成 accept（`synthesis.py:399`，经 `synthesis.accept_candidate` 透传）两个真实调用点自动被覆盖，未来导入/批量出口也自动过闸。create 路**复用既有 `get_chunks_by_ids` 取行**（实体派生同一次取数，不二次查库）。题库**没有编辑口**（路由只有 create/delete/accept，改题=删+建）⇒ 删建路径天然过闸。guard 可注入（默认关，调用方传 store 取正文的实现），保持 add_question 的文件层纯度与现有测试形状。

**交互细则（2026-10-05 他拍 B′：行内红字 + 按钮换文案，不进弹窗）**——UI 三处共用同一套（①新建考题表单 `eval-add-question-dialog` ②召回测试"存为 golden" `eval-save-question-dialog`——与①是**两个组件**、共用同一提交端点与同一交互 hook ③合成候选「接受」`eval-synthesis-review`）：

- **第一次点「保存」**：有反应、**不入库**——按钮行正下方出行内红字明细块（复用现有表单错误的行内位置，**不新增弹窗、不新增常驻控件**），内容=机器依据：miss 术语表 + 建议锚（如 `miss: 装箱 拆箱` / `建议锚 #0001（3/3 vs 1/3）`）。
- **看完明细二选一**：改锚 ⇒ 再点「保存」（锚对即机器放行入库）；坚持原锚 ⇒ 红字块里**变出**「仍要入库」按钮（警示色；合成审核面为「仍要接受」），点它才带一次性确认标记入库。**确认动作必须是变出来的那个按钮**——原「保存」保留为复检键、重复点它不入库（盲双击≠看见，这是"人做最后检验"的物理保证；2026-10-05 落地时把"按钮换文案"收敛成这一形态，原按钮文案不动）。
- **合成口同款**：被拦的候选行内出红字明细 +「接受」变「仍要接受」（候选详情页本有明细位，零新布局）。
- 三个 UI 口子落到后端是**同一个收口**（见上），所以拦截交互在前端只写一份、三处复用。

**存量修复**：q008 按 D3 裁定修锚；运行库与 git fixture 两份同步改（fixture `backend/tests/fixtures/rag_eval/golden.jsonl` 同错）。审计脚本留 scratch 不进仓（探针先例）。

## 4. 硬约束

- 核验**零 LLM、纯本地字符串操作**；不新增依赖（jieba 不进核心）。
- **检查函数只写一份**，所有出口共用；收口在题库唯一写路径。
- **两条豁免写死在判据里**（无参考答案跳过；多片题只拦单片零命中），不是可选项。
- 拦截**必须回显机器判定明细**（术语命中表 + 同文档建议锚），不静默拒绝；明细走**结构化 detail**（键：`miss_terms` / `suggested_chunk` / `hits` / `best_hits`，异常类独立于 `QuestionBankInvalidQuestion` 的纯字符串 detail）。确认绕过是一次性请求级标记，**不进题库 schema**（被绕过的题与机器放行的题在数据上无差别，只留日志痕迹）；**锚失效（片不存在）不给确认绕过**——确认了数据也是坏的，绕过只留给术语级拦截。
- 不动 dataset schema、不动评测指标口径；题库 fixture 与运行库的其他差异不属本对。
- 语义级"答非所问"**不归机器**——留人眼终审（合成路本有人点接受那一步，机器核验放在人眼前面）。

## 5. 验收

1. **TDD 红例**：q008 形状（答案术语锚内低命中、同文档他片全中）⇒ 创建被拦（红=今天无门禁、创建成功）；空答案放行；多片 BEATEN 放行；多片单片 ZERO 拦。
2. **双口同检**：create 与合成 accept 都过 guard（stub 模式照 `test_synthesis.py` 先例）。
3. **neuter**：拆豁免 ⇒ 假阳例红；拆收口（只挂 create）⇒ accept 例红；放宽判定阈值 ⇒ q008 形状例红。
4. **存量**：q008 修锚后复跑审计 **✓14/✗0/—5**；L1 分数口径登记（改锚后 q008 与历史分数不可比，`eval_runs` 基线按需重标）。
5. **门禁面**：eval 面 + knowledge API 面全绿 + ruff 双净。
6. **前端交互三钉**（B′，dom 用例先例=recall-test-panel）：被拦 ⇒ 行内红字明细块出现且**不入库**；按钮换文案「仍要入库」后点击才入库；**重复点原「保存」不入库**。合成口「仍要接受」同款。
7. **真栈**：UI 手工创建一道 q008 形状贴错题被拦（响应含明细）→ 点「仍要入库」入库成功（甲′ 绕过路径）→ 改正锚再存亦成功；合成 accept 过闸路径通；收尾临时题删净、配置零改动。

## 6. 非目标与登记

- **语义级核验不做**（片内有术语但答非所问）——人眼终审，不引 judge 进门禁（judge 方差不进门禁是既有裁定）。
- **行内状态徽章**（题库行挂"标注核验 ✓/✗"）= 二期登记，等实例触发。
- **重入库/重切片后自动重验** = 二期登记：`chunk_id` 是 `{doc_id}#NNNN` 序号制，重切会移位使标注静默失效——真场景，等发生一次再做。
- **无参考答案 5 题**（q017–q019 + 测试2 两题）机械核验覆盖不到 = 已知缺口，不补答案（global 题本无单句答案）。
- **q_6d995a36 `rel=0`**（零锚片+无答案）= 坏题气味，登记待处置（测试2）。
- **q009"可能漏贴 #0002"**（两锚 2/4、1/4 而他片 3/4）= 提示级留人眼，不入本对范围。
- **抽象短答案被拦一次**（如「综合。」这类与锚定片零词面重叠的短答案，Task 1 实测受害者夹具即是）= 设计内行为（机器要求看一眼、人点「仍要接受」过）。登记观察：若实际使用中短答案误拦频发，再议第三豁免「术语集 |K|<2 免术语核验」——判据两口径（jieba/二元组）实测均零误报，先不动。
- 审计脚本（scratch `golden_audit.py`）是一次性工具，不进仓。
