**本对一件事：把题目锚定从「看得见文档、看不见切片、改不了、失锚也不知道」补齐成——锚定可见（切片内容级）、可改（抽屉内、过同一道锚定核验）、悬空有标（重切片/删片后标出悬空锚）。**

术语约定：**悬空锚** = `relevant_chunk_ids` 里的切片 id 在该库 `chunks` 表中已不存在（重切片重排序号、或切片被删导致）；**改锚** = 只改 `relevant_chunk_ids`（实体随锚派生，见 D4）；**复检键** = B′ 交互里永不带确认标记的原「保存」按钮（盲双击不落库的物理保证）。

来源：2026-10-05 用户两截图 + 六连定性（「没有切片信息只有文档信息 / 改不了锚定 / 只有 LLM 才能有锚 / 2 就是具体体现 / 出问题只能重新生成」）；上一对 `2026-10-05-rag-golden-anchor-guard-design.md` §6 登记项「重入库/重切片后自动重验」核实为真缺口（`_reparse_and_chunk` wipe+重切挂重试路），本对收编其「标记」半边并新增改锚口。

## 1. 问题（机制与证据链）

现状三缺口（逐条实证）：

1. **看不清**：详情抽屉参考文档卡（`frontend/src/components/workspace/knowledge/eval-question-drawer.tsx:43` `groupChunksByDoc`）只显示「文档名 + `#稳定序号` 徽章」——序号是从 id 字符串切出来的（`chunkId.split("#")`），**不查库、不显示切片正文、无跳转**。锚悬空了照样渲染（字符串还在），看不出来；两篇文档各自的 `#0000` 观感上「只有文档信息」。
2. **改不了**：题库路由只有 create/delete/accept（`backend/app/gateway/routers/knowledge_bases.py:747–850`），无更新端点；`question_bank` 只有 `add_question`/`delete_question`。改锚 = 删+重建（旧裁定：编辑不支持、改=删+建）。**当时理由**=手填锚易贴错、锚定正确来源是召回面板「存为考题」；**理由今天已被搬掉**——锚定核验（`eval/anchor_check.py`）落地后，改锚可走同一道闸（贴错当场拦、悬空锚无条件拦、人可确认放行），「不敢让人改」不再是安全前提。
3. **失锚无感**：`_reparse_and_chunk`（`backend/packages/harness/deerflow/knowledge/worker.py:698`）重试/续传整篇 wipe+重切，`{doc_id}#NNNN` 序号移位；切片删除（`DELETE /{kb_id}/chunks/{chunk_id}`）同样造悬空。两路都不触碰题库 ⇒ 题目静默失效（该锚永远进不了 hits：单锚题整体恒 MISS，多锚题 recall@k 分母虚高、永久打不满——`metrics.py:91` 口径 `recall@k = |relevant∩hits|/|relevant|`）。这正是「2 就是具体的体现」的机制：失锚本身是文档线的正常后果，**看不出来 + 看出来也改不了**才把它放大成只能删题重建。

**顺带澄清（不是缺陷，防再误读）**：「只有 LLM 才能有锚」不成立——三条来路是 添加框=无锚（故意）/ 召回面板「存为考题」=人工带锚 / LLM 合成=带锚。人工一直可以有锚，只是添加框不设入口（该入口候选仍开，见 §6）。

## 2. 方案

### ① 锚定可见（抽屉参考文档卡升级）

参考文档卡从「文档名+序号徽章」升级为**逐片 ChunkCard**（复用 `frontend/src/components/workspace/knowledge/chunk-card.tsx`，wiki 血缘抽屉先例 `wiki-entry-drawer.tsx:161`；**只读=不传 `onEdit`/`onDelete`/`onReExtract` 动作回调**——组件自带这些可选动作，抑制即纯展示，避免与改锚编辑态两套编辑口：它自带的编辑是改切片正文，另一根轴）：一次 `listChunksByIds`（`api.ts:227`）取锚定片正文 + `doc_name`，**同一取数两用**——正文预览（看得见切片内容）+ 返回差额即悬空判定（服务端静默丢缺片，`knowledge_bases.py` `list_chunks_by_ids` docstring 明记 "Unknown ids drop silently"，请求集 − 返回集 = 悬空集）。序号徽章保留（稳定身份，与切片抽屉位置序的既有区分不变）；悬空的片在卡内单列一行警示。

**只读态不铺全量**（2026-10-05 他确认）：平时只显示**已锚定的那几片**内容卡——参考文档卡回答"这题答案锚在哪"，文档其余切片与本题无关、摆出来是噪音；文档全量切片只在**编辑态**出现（见 ③）。

### ② 失锚标记（读时派生，不落状态）

`list_eval_questions` 响应每题加 `missing_chunk_ids: string[]`（服务端对全部题的锚 id 并集一次 `store.get_chunks_by_ids`（`store.py:326`）派生，50–100 题规模一条查询）；题库行**参考切片格**挂警示徽章（**有悬空才显、无悬空零变化**；行内徽章=二期登记项由本实例触发转正，仅标存在性、不标词面 ✓/✗）。抽屉卡头同源显示。**不落盘、不在重切片/删片路径写标记**：读时派生永不陈旧、零跨线写（文档线不该写题库）。

**列口径改造（2026-10-06 他裁甲：数字与中文量词不在数值格混排）**：该列现显示 `N 篇`（`refDocsCount`，数字+中文量词混排，且与抽屉「N 切片」徽章两种数对不上）⇒ 表头 `参考文档`→**`参考切片`**（单位进表头、表头自解释），格子**纯数字**=切片数（与抽屉「N 切片」徽章同数同口径）；`refDocsCount` 退役；hover tooltip 文档名列表保留（篇数=列表行数，不再单列）。2026-09-07「计数+单位消歧义」职责从格子**搬进表头**，非推翻。

**排序保篇序（2026-10-06 他裁：排序按篇落）**：排序比较器**不动**（`eval-question-bank.tsx:220` `refDocIds().length`，语义=跨文档广度——哪些题锚跨多篇即综合题）；排序项 label 从共用 `columnRefDocs` 改为自解释的**「文档数」**。显示=片数、排序=篇数，**不同轴但 label 各自说清**（他"表头自解释"判据）；「比较器改片数」的原方案作废。

**波及面（二轮审查实证，全在本对动的组件内）**：
- **合成候选卡同单位承诺**：`eval-synthesis-review.tsx:255` 注释明写「与题库参考文档列同语言…采纳前后同一单位」、`:279` 用 `refDocsCount` ⇒ `refDocsCount` 退役波及它，候选卡**同步改切片纯数字**（否则采纳前 1 篇/采纳后 2 片，恰违反其自身注释）。
- **i18n 键分家三处使用点**：`columnRefDocs` 现被三处共用——表头 `:331`、排序选项 label `:205`、抽屉卡头 `:155` ⇒ 表头用新词「参考切片」、排序选项用新词「文档数」、**抽屉卡头留「参考文档」**（它装的是文档分组）。en-US 侧 `Ref docs`/`${count} docs` 与 `types.ts:689-691` 注释随口径改。

**警示徽章样式**：`<Badge variant="destructive">` 小号纯词**「悬空」**——对齐同 tab 回归徽章「检测到回退」先例（`eval-metrics-overview.tsx:77`）：纯文字、无数字（几片坏去抽屉逐片看）、无图标、颜色走 destructive token 不自造。

**悬浮统一（封闭清单两处，只换 DOM 原生 `title` 属性）**：① `eval-question-bank.tsx:419` 问题列 `title={question.query}`；② `eval-question-drawer.tsx:171` 参考文档组头 `title={docTitle(...)}`——两处均换项目 Tooltip 组件（Radix 主题样式，与文档名 tooltip 同款）。⚠️ `eval-metrics-overview` 的 `MetricTile title=` 是组件 prop 非 DOM 原生悬浮，**不动**。

### ③ 改锚（抽屉内编辑，过同一核验）

- 后端**唯一新增写入口** `question_bank.update_question(path, question_id, *, relevant_chunk_ids, relevant_entities=None, anchor_guard=None, anchor_ack=False)`：与 `add_question` 并列收口，同 `_lock` 读改写 + `_atomic_write`；query/category/expected_paths/reference_answer 等**不动**；清空勾选=解除锚定（变无锚题，与添加框产物同态，**允许**）。挂**同一 `anchor_check.build_anchor_guard`**（store 取正文；`missing_chunk` 无条件拦、ack 也放不过）。
- 服务 `update_eval_question(kb_id, question_id, *, relevant_chunk_ids, anchor_ack)`：一次 `get_chunks_by_ids` 喂核验正文 + 实体**跟锚收缩**（D4=甲′：旧实体 ∩ 新锚实体词汇表——只删失去支撑的、**不新增**；合成题精选子集保住，create「显式非空尊重原值」契约不破坏）；router `PATCH /{kb_id}/eval/questions/{question_id}`（过 `_require_kb_access`，与 create/delete 同权；body：`relevant_chunk_ids` + `anchor_ack?`）→ 200 题体 / 404 / 422 结构化 detail（与 create 同一 `AnchorMismatchError` 映射，detail 键 `reason`/`miss_terms`/`hits`/`best_hits`/`suggested_chunk` 不变）。
- 前端：抽屉参考文档卡加「编辑锚定」入口 → **折叠分组勾选区**（D3 细则，2026-10-05 他展开）：组头=文档名 + 「已选 n/N」计数、**默认收起**（含已锚片的文档默认展开）、组内=该文档全部切片（每片内容摘要行+勾选框、已锚默认勾上）、**组内分页**（`listDocumentChunks` 50 片/页滚动加载）、**勾选后可整组收起**（组头计数实时变 ⇒ 整卡高度上界=文档数×一行组头，文档多也不撑长）。复用 `listDocumentChunks` + 文档列表词汇，不手填 id。拦截交互**原样复用 B′**：`useAnchorConfirm`（keyed=抽屉）+ `AnchorBlockNotice` 红块，红块里**变出**「仍要保存」；原「保存」留复检键、重复点不落库（盲双击≠看见）；悬空锚不可确认绕过（与写入口同语义）。**悬空锚在选片区单列可摘除行**（序号徽章 + 「悬空」+ 勾选框，与读态警示行同款）——悬空锚随草稿播种但不在存活切片列表里，缺这行它就无从摘除、`missing_chunk` 恒拦成死锁（真栈验收 2026-10-06 发现并当场补上，`d647f656f`，新口径=读态警示行的可摘除版）。

### ④ 读时词面徽章（2026-10-06 追加：落空半边，A1/A3 并入）

**锚定片三态成表**（本对 §1「失锚无感」的完整收口）：① 无锚题＝不标（没有锚就没有锚错问题）；② 锚指向的切片**没了**＝「悬空」（② 已交付）；③ 切片还在、**内容被换**（重切同号不同文 / 切片正文编辑）＝今天无任何标记、看着全绿——**本节补的就是 ③**。检测不挂重切钩子、不写状态：`list_eval_questions` 读时派生（与 `missing_chunk_ids` **同一次取行**、同一 `check_anchor` 判据 + 门禁两条豁免），响应每题加派生字段（判定 / 命中 / `suggested_chunk`），永不陈旧（D1=甲 同款哲学）。

**只标记不动手**（重切失锚三档里的甲语义）：机器只打徽章 + 给建议锚，不改锚不删题不改分数；修复＝点「编辑锚定」走 ③ 勾选区（同一道闸把关）。界面三个落点（全在现成格子里）：**行级**「参考切片」格第二类纯词徽章「**存疑**」（B1=甲；有疑才显、无疑零变化；amber 档＝可确认待人看，与 destructive「悬空」的已坏不可绕分档——沿用红块确认钮的 amber 词汇）；**悬浮**＝项目 Tooltip 机器依据（命中表 + 「建议锚 #0001（3/3 vs 1/3）」，红块同款文案）；**抽屉**疑片行内同款（徽章随折叠触发行、收起态也可见）。**派生形状**：响应每题 `anchor_mismatch`（`reason`/`miss_terms`/`hits`/`best_hits`/`suggested_chunk` + 疑片 `chunk_ids`）或 `null`；疑片集由判定层 `AnchorVerdict.chunk_ids` 给出（单片贴错=该片、多片零命中=全部零命中片，**不进 detail 五键 wire 契约**）。**悬空优先**：有缺片时 `anchor_mismatch` 恒 `null`（`check_anchor` 缺片短路同一判定）——一题至多显一类警示，修完悬空落空自会浮出。豁免照抄门禁：无参考答案不标、无锚不标、多片只看单片零命中；**抽象短答案（|K|<2）不豁免**（B2=乙：它是标记非拦截，实例出现再议第三豁免——上轮核实 39 题 0 实例）。收编锚定门禁对 §6 登记项「行内标注核验 ✓/✗」的**词面半边**（存在性半边已由「悬空」转正）。

### ⑤ 参考文档片级折叠（2026-10-06 追加：长片撑爆抽屉，C1=甲）

**问题**：读态逐片 ChunkCard 是全文卡（正文 + 实体 + 页脚度量 + 渲染/原始切换），单片长文一铺就把参考答案/实体/底部动作栏顶出视口——抽屉里不止参考文档一节，通读不该挤掉其他节。**做法（甲）**：`#序号` 徽章行升级为**折叠触发行**（勾选区组头同款词汇——ChevronDown `rotate-180` + `aria-expanded`）：收起态（**默认全收起**）在行下显 `chunkPreview` 两行摘要（与编辑勾选区切片行**逐字同口径**）；展开才落整张 ChunkCard（现状原样，渲染/原始切换随卡）。折叠集按 chunk id 稳定身份存抽屉本地 state；**不碰共享 `ChunkCard`**（切片抽屉仍全文展示，零波及）；悬空行无内容可折、保持单列警示；编辑勾选区本来就是折叠结构、不动。取舍：核对某片内容多一步展开——换整抽屉可扫（query → 参考答案 → 一屏片单 → 实体 → 动作栏）。

## 4. 硬约束

- 核验**零 LLM、纯机械**；检查函数**不写第二份**——改锚与 create/accept 共用 `anchor_check` 族与同一 422 结构化 detail 键。
- B′ 交互细则原样适用：原按钮=复检键永不带 ack；确认钮=红块里变出来的那个；`missing_chunk` 不给确认绕过。
- 改锚**只动锚**：题面/分类/预期路径/参考答案不动（改答案=登记项，词面核验耦合答案，混改把两轴判定搅在一起）；题库 schema 不动——`missing_chunk_ids` 是响应派生字段，**不进 `golden.jsonl`**。
- 读时派生标记不落盘；重切片/删片路径零改动（worker 线不碰题库）。
- 单写入口纪律：`update_question` 与 `add_question` 并列收口，guard 注入形状一致（默认关=文件层纯，既有直调用例零扰动）。

## 5. 验收

1. **TDD 红例**：update 口贴错锚被拦（红=今天无 update 口/无闸）；悬空锚改锚提交被拦且无确认绕过；合法改锚 200 且实体**跟锚收缩**（失去支撑者删、不新增——精选子集保住）、其余字段原样钉死；清空勾选=解除锚定落库为空；list 响应 `missing_chunk_ids` 悬空/存活两态正确。
2. **neuter**：update 拆 guard ⇒ 贴错改锚例红；拆实体重派生 ⇒ 实体脱钩例红；list 派生改恒空 ⇒ 标记例红。
3. **前端 dom 三钉**：抽屉逐片卡渲染 + 悬空徽章；编辑保存被拦 ⇒ 红块变出「仍要保存」且不落库、原按钮盲重复点仍不落库；确认钮携 `anchor_ack=true` 落库。**表格侧三钉**：参考切片格纯数字（无量词混排）+ 纯词「悬空」徽章仅悬空题显；问题列悬浮走项目 Tooltip（无原生 title）。
4. **门禁面**：eval 面 + knowledge API 面 + 前端全量 + `ruff`/`pnpm check` 双净（零新增红，环境红带口径照旧）。
5. **真栈（仅测试2）**：临时文档（≥2 切片）→造题带锚→删锚定那片（留另一片当改锚目标）→行级/抽屉悬空标出现→抽屉改锚（误锚被拦→红块「仍要保存」放行 / 正锚直过）→实体随锚收缩→收尾删题删文档、配置零改动。
6. **追加 Task 5（落空词面）**：TDD 红例＝落空题（锚在、答案词面零命中/被压制）list 响应带派生判定 + 行级「存疑」徽章 + Tooltip 命中表与建议锚（红=今天无派生字段无徽章）；好题零标、无参考答案不标、无锚不标、多片单片零命中才标；neuter：豁免拆掉 ⇒ 无答案例恰红、派生拆掉 ⇒ 徽章例恰红。**真栈**：造落空题（锚贴到不含答案词面的片）→行级/抽屉「存疑」+Tooltip 建议锚→抽屉改锚改对→徽章消失→收尾删净。
7. **追加 Task 6（片级折叠）**：dom 红例＝默认收起显摘要行、正文不渲染（红=今天正文全量渲染、无触发行）；展开落整卡（正文可见、仍无编辑动作）、再点收起正文让位回摘要；悬空行无触发行不折。**真栈**（并入下次验收）：长片题打开抽屉一屏见多节 → 展开单片核对 → 收起复位。

## 6. 非目标与登记

- **改参考答案/题面/分类/路径**的编辑口不做——登记（答案编辑与词面核验耦合，单起）。
- **自动改锚**（悬空自动重锚到建议片）不做——登记（机器建议锚已有 `suggested_chunk`，人来点；机器要求看一眼、不否决人）。
- L1 计分对悬空锚的既有口径**不改**（该锚永不命中：单锚题恒 MISS、多锚题 recall@k 每条悬空锚拖 1/|relevant| 永久打不满）——本对只让其可见；历史 `eval_runs` 不重标。
- **添加框「勾选切片区」候选**仍开（与本对并列待拍：本对做抽屉改锚后，添加框带锚的紧迫性下降，可维持"要锚走召回面板"分工）。
- 合成候选暂存不支持改锚（候选=出题时刻快照，接受前可拒绝重合成）。
- 抽屉切片卡「点开切片抽屉」跳转不进本对（预览已够核对；跳转随 ChunkCard 先例自然长出）。
