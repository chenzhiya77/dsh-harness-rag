# 外部稀疏服务的连通性探针 —— 设计

**Parent:** [2026-09-16-rag-sparse-capability-probe-design.md](2026-09-16-rag-sparse-capability-probe-design.md)（模型级能力探针：这条线已有的那个探针，本 spec 是它的**增量**）
**Status:** 已交付 2026-09-17

## 1. 问题

三条稀疏来源里，只有「独立稀疏服务」（`external`）**要用户填地址**。而它的配置错误——**地址填错 / 服务没起 / 路径不对**——在保存期**抓不到**：`TEISparseEncoder` 的构造期校验只问"地址是不是空的"（不出网）。于是这类错误要等**入库或检索**才暴露，表现形式还是"部分切片失败"或该路报错，**不是一句"你的稀疏服务连不上"**。

嵌入侧已经有同款的"真打一次、只读、不落盘"的探针（父 spec §3 D3）；本 spec 把同一形状补到**外部稀疏服务**这一格。

## 2. 决定

### D1 —— 端点：`POST /api/rag/config/probe-sparse`

照父 spec 那个探针的每一条：admin 门控；请求体 `extra="forbid"`；**只读不落盘**；**不返回密钥**；`detail` 折叠空白并截断 200 字符；**有界超时 10s**（沿用 `_PROBE_TIMEOUT_SECONDS`）；失败**返回状态而不是抛**。

请求：`{sparse_provider, sparse_base_url?, sparse_api_key?}`。`sparse_api_key` 允许**掩码哨兵**（＝用已存/环境的那把），与环境名按**候选 provider** 解析（复用 `_secret_env_name("sparse_api_key", …)`）。
非 allowlist 的 provider id（含空串）⇒ 422：这一格没有"由服务决定"的语义，`external` 本来就要求一个具体 provider。

### D2 —— 三态：`ok` / `empty` / `unreachable`

| 状态              | 判定                                                      | 界面                                          |
| ----------------- | --------------------------------------------------------- | --------------------------------------------- |
| **`ok`**          | 调用成功 + 形状正确（每条输入一个数组）+ **至少一个词项** | 无话                                          |
| **`empty`**       | 调用成功 + 形状正确 + **该文本一个词项都没给**            | 一句**警告**（不拦）                          |
| **`unreachable`** | 连不上 / 超时 / 鉴权被拒 / 形状不对 / 批量条数不符        | 一句**警告**（不拦），`detail` 带原因与状态码 |

- **`empty` 单独成态的理由**：这正是这条线在治的那类"静默降级"——服务通、但每个输入都回空稀疏，检索会悄悄少一半信号。把它与"连不上"分开，用户才知道该去查模型而不是查网络。
- **都不拦保存**：服务可能稍后才起；把"暂时连不上"升格成"不许保存"就是父 spec 里 `unverifiable` 那条教训的重演。**探针只报，不拦**（这一条与"编辑期拦下 dense-only"是两回事：那一个是**已经确定**的不支持）。

### D3 —— 判定走运行期那一段，不另写

直接取 allowlist 里那一行（`resolve_provider("sparse", sparse_provider)`）构造它的实现类，`await encoder.encode([_PROBE_TEXT])`。
**不经过 `build_embedder`**：那会把稠密侧一起建出来，而这条腿的问题与稠密配置无关（用户可能正处在改稀疏配置的中间态）。

### D4 —— 界面：状态骑在**接口地址**那一行

- **位置**：`接口地址` 那一行（填错时你要改的正是它），沿用刚立的规矩——**状态骑在字段内、尾部插槽**（`trailing`），零位移。
- **触发**：来源 = `external` **且** 地址非空 ⇒ 防抖 400ms 后发一次；**同一候选只探一次**（键 = `provider|base_url|是否有 key`；换地址/换 provider/增删 key ⇒ 作废重探）。
- **结论绑定**：同上，与当前值不符的旧结论一律按"没有结论"处理。

### D5 —— 不做

- **不**做质量评测（不比对、不落库、不缓存）——判据是"通不通"和"给没给词项"。
- **不**给 `provider` / `bm25` 两条路做探针：它们不出网（前者是平台调用由能力探针覆盖，后者本地零服务）。
- **不**改保存期校验：探针是**知情权**，不是门禁。
- **不**做会话级缓存（与父 spec D7 同）：唯一后果是每次打开设置页、若处在 external 且地址已填，会多打一次真实调用（有防抖与键绑定）。

## 3. 接口契约

| 端点                                      | 变化                                                                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/rag/config/probe-sparse`（新） | admin；只读不落盘；`{status: "ok" \| "empty" \| "unreachable", detail}`；有界超时；不返回密钥；非 allowlist provider ⇒ 422 |

## 4. 验收

1. 桩一个**正常返回稀疏**的服务 ⇒ `ok`；
2. 桩一个**返回空数组**（`[[]]`）的服务 ⇒ `empty`（**不是** `ok`，也不是 `unreachable`）；
3. 桩一个**连不上**的目标 ⇒ `unreachable`，`detail` 带原因；
4. 桩一个 **401** ⇒ `unreachable` 且 `detail` 含状态码；
5. **不落盘**：调用前后 `rag_config.json` 逐字节相同；响应体**不含**提交的 key；
6. 未知/空的 `sparse_provider` ⇒ 422；
7. 非 admin ⇒ 403。

**前端**

8. 纯函数：结论按 `provider|base_url|是否有 key` 绑定，键不符 ⇒ 无结论；
9. dom：来源 `external` + 地址非空 ⇒ 发一次探测（断言请求体）；**地址为空 ⇒ 不发**；`unreachable` ⇒ 该行给出警告且**Save 不被拦**；
10. 状态骑在**接口地址**字段内（`closest('[data-slot=…]')` 结构断言），与父线的 `trailing` 规矩一致。

## 5. 影响面

`backend/AGENTS.md`（RAG 配置一节补新端点）、`frontend/AGENTS.md`（功能模型一节补这条探针与"只报不拦"）。无迁移、无 schema 变更、不动任何默认值。
