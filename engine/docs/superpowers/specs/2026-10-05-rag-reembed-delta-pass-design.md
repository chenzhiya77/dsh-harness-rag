## 1. 问题（机制与证据链）

同宽换模型保存（D3）的就地重建是**一遍过行走**：`rag_reembed._run` 逐库 `reindex_kb` 重嵌现存行，全部走完才原子翻转配置。`reindex_kb` 的走法是**开跑拍一次文档快照、对快照穷尽走**（`reindex.py:137`）——快照里的每个文档都会被走到；漏网的不是「游标后面的行」，而是**快照之后才出现/才完成的文档**（列表里根本没它）。两个事实叠出洞：

1. **窗口里完成的新文档由 worker 按被 hold 的旧配置嵌入**——hold 是有意的（窗口里查询侧与新写入在旧空间自洽），代价是这些文档的向量落在旧空间。
2. **快照有缝**——缝里的文档不被这遍行走覆盖，且分两半：快照里已存在但当时非终态的文档今天是「跳过 + `complete=False` ⇒ 不盖章」（`reindex.py:155-158`），只是静默混用、**不谎报**；快照缝里那批行走根本看不见，完整性闸保持 True ⇒ 翻转后 D2 盖章「本库向量=新空间」是**假声明**，D4 也看不见（身份与配置一致，失配不响）。

后果：那篇文档的切片**永久静默漏检**（旧空间向量 vs 新空间查询 cos≈0——与本对源头根因「322 条 stale 向量」同类病、换个产生者）。

- 触发面：每遍重建窗口（A4 实测 4.5 / 3.75 分钟）内有文档完成入库；触发后永久、静默。
- 现成先例：宽度迁移通道（`dimension_migration.migrate_collections`）早有同款二遍（`include_non_terminal=True`，`reindex.py:117` 现成参数）专门收「迁移窗口里没跑完的文档」，且带**内容指纹门**（`_content_mark` 基线对比，没动过的库零嵌入跳过，`dimension_migration.py:141-165`）——D3 新写时没抄这半，属遗漏非裁定（2026-10-04 Task 2 发现，spec §2.3 已记账）。
- 活体证据：A4 看守日志两遍同序（库逐个盖章 1→2→4→5 期间文件恒 hold 旧值、5/5 才翻）——顺带可见中间态正是 D4 短暂失配窗口。

## 2. 方案

翻转后对**动过的库**补走一遍 `reindex_kb(..., include_non_terminal=True)`：配置已切新模型，此后 worker 的新写入都是新空间；delta 复走把**翻转前写入、主行走快照没覆盖**的行补进新空间。门槛与宽度通道同构（审查裁定甲）：重建开始给每库拍 `_content_mark` 基线（`store.get_kb_content_stats` + 文档 id 集，chunks/wiki/cards/entities 四信号），翻转后对比——**没动过的库花一次聚合查询、零嵌入**（宽度通道原注释 "the common case stays free"），动过的库才整库复走。门不受重建自身写入污染：`index_chunks`/`update_document_status` 只碰 documents 表，四个信号一个不涨。

窗口的单向门是翻转：delta **必须**在翻转后跑才有封闭的目标集（翻转前跑，行还在不断到达）。因此盖章时序也要跟着动（D2）。时机与宽度通道相反也在此：宽度通道的二遍在**切换前**（新代未活，另需 `_drop_documents_that_left` 收尾）；本对 in-place、删除走自己的路，不需要那件，且必须在**翻转后**。

**GREEN 期定形（2026-10-05）：章按两条分支落。** 复走过的库由 delta 自身的完整性盖（`reindex_kb` 现成语义）；**未动的库由主行走的完整性判词盖**（未动+完整=均匀，未动+软失败=不盖）——否则门槛跳过的库永远没人盖章（RED 期当场翻出）。`reembed_libraries` 因此逐库交出判词（`ReindexReport.complete`）。

**已知盲区（登记）**：指纹门的实体信号只有 `count`（`store.py:318`；`graph_entities` 表无时间戳列）——「同数实体描述编辑、且其余四信号全不动」的改动过不了门。实况核对：描述写入全挂在抽取/归一/别名合并路径（`graph/normalizer.py:205`、`graph/store.py:80/244/285`），必伴随文档切片落库（chunks 信号会动）⇒ 未指认到独立触发路径。按登记不做；若日后出现该形态，补列 `updated_at` 进指纹即可关掉。

**并入件 ③（2026-10-05 他拍甲）：重建通道加固。** 两半叠出（flake A/B 实锤、HEAD 同在，非新回归）：①`atomic_write_rag_config` 的 tmp+`os.replace` 在 Windows 上撞上不带 `FILE_SHARE_DELETE` 的读方（load `rag_config_file.py:226` / 签名检查 `file_signature.py:49`）⇒ `PermissionError(13)`；②`rag_reembed._run` 的翻转写在 try/except 之外（:145-146）⇒ 任务带异常死掉、状态永远卡 `running`，此后所有保存被 409 挡到重启（409 死锁）。修姿：翻转写纳入失败记账（失败 ⇒ 状态 `failed` + 日志，绝不留 `running`）；replace 撞车按瞬态**有界**重试（3 次、50–100ms 退避），耗尽按翻转失败处理——无界重试会把「读方一直开着」变成任务悬挂。重试落写文件助手（生产调用方只有 `write_rag_config` 一个，所有写方受益）；读方姿势不动。

## 3. 决策点（已裁 2026-10-05：D1=甲、D2=乙、③=甲；同日审查追加：复走门槛=甲）

- **D1 delta 复走的范围 = 已裁甲**：翻转后一遍 delta——洞从「整个行走窗口」缩到「单文档的嵌入时延」（宽度通道同款姿态、同款残余）。乙（收敛环，delta 后再复核直到空集）未选：多一层循环与判定，尾部残余登记不做闭环。
- **D2 盖章归属 = 已裁乙**：章改由 delta 走完才盖——主行走带 `stamp=False`（`reindex_kb` 参数化、默认不变），delta 完整走完才写身份。失败面由此诚实：**delta 失败 ⇒ 章留旧值/NULL ⇒ D4 失配可见**、重跑即愈。甲（主行走照盖）未选：失败后章仍是假声明且无人看得见，与本对目的相反。
- **复走门槛 = 已裁甲（审查后追加）**：指纹门同构宽度通道（基线对比，没动过的库零嵌入）。乙（每库必复走，每次重建固定 2× 嵌入——A4 口径单遍 163 调/4.5 分钟）未选：低频事件也不该白付双倍。

## 4. 硬约束

- 不动 worker 写序、不动 hold/flip 语义、不动宽度通道（`migrate_collections` 及其二遍零改动；只抄它的门与调用形）。
- `reindex_kb` 默认行为零变化（`stamp`/`include_non_terminal` 均 opt-in），旧调用方（worker、手动重建 `knowledge_service.py:1755`、存量脚本）语义不动。
- 失败词汇定形：`failed` 只给 raise（库级/写盘异常）；走完但软失败（文档失败/批 `indexed<total`）= `succeeded` + 不盖章 + D4 可见——与「旧索引继续服务」的失败姿态一致，不翻回、不遮掩。
- ③ 同姿态：翻转写失败落 `failed`、replace 撞车有界重试不打死任务；改动面只在 `rag_reembed._run` 与写文件助手，读方姿势不动。
- 尾部残余（单文档嵌入时延）登记不做收敛环（与宽度通道同口径；D1 已裁甲）。

## 5. 验收

1. 单测（D2=乙）：主行走完成不写身份；delta 完整走完才写（=当前指纹）。
2. 单测：两遍之间插入完成的文档（快照缝）⇒ delta 把它补进新空间。
3. 单测（门槛）：窗口里没动过的库零嵌入跳过（只花聚合查询）；动过的库整库复走。
4. 单测：delta raise ⇒ 身份留旧值/NULL、状态 `failed`，重跑修复；软失败 ⇒ 状态 `succeeded`、无章、D4 判词可见。
5. 单测（③）：翻转写抛异常 ⇒ 状态落 `failed`（不是永驻 `running`）、后续保存不再被 409 挡死；replace 瞬态撞车 ⇒ 有界重试后成功、任务不亡；重试耗尽 ⇒ 按翻转失败落 `failed`。
6. 真栈验收：触发重建 → 窗口里塞一篇文档 → 验 delta 把它补进新空间、章最后落、D4 静默；配置逐字节还原（老配方）。
7. 门禁：knowledge 面（环境红按既有账）+ ruff check/format 双净。

## 6. 非目标与登记

- 不做收敛环尾部关闭（D1 未拍乙）；
- 不改 D2 身份编码/写入两处的既有规则（`reindex_kb` 完整性闸、worker 首件闸原样）；
- 不做 D4 的观测面扩展（失配提示仍是 recall-test 一处）；
- 与物化默认键小补丁（rag_config 写路径，已交付 `bd61109db`）无关；
- 登记三件（审查 7/8/9）：①孪生竞态=`atomic_write_models_config`（models_config.py）同构 tmp+replace 无重试，本对只修 rag 路径；②清扫的 `busy_kb_ids()` 不含重建在飞（按清扫判据「行不存在才删」无交界风险），要不要让清扫绕行重建=可选；③delta 复走会让 `reindex_kb` 的进度快照中途重置（每调用一份，纯观感）。
