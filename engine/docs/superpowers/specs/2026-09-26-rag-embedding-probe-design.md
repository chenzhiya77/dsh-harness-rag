## 1. 问题

### 1.0 一眼看懂

目标流程（他给的形态）：**按维度档位先探 → 把探测结果放出来 → 用户选 → 库按所选维度建/重建**。落档为 D1 乙；本文主线即这四段。

两件事、两种现状：

| 他问的 | 现状 | 一句话 |
| --- | --- | --- |
| 这模型**支持哪些维度**？先测出来，再由人选择 | **不探**；维度是**存储契约**（集合创建时钉死 1024），不是可选项 | 唯一"我们主动吃亏"的口子是 **F2**（见 1.1） |
| 这模型**一批能吃多少**？按它设置 | **静态表**（10 / 20 / 1），无任何配置键 | 猜大的后果是**该批失败**，猜小只是**慢** —— 兼容/效率问题，不是正确性问题 |

### 1.1 现状 · 维度（四层，逐层给落点）

| 层 | 现状 | 落点 |
| --- | --- | --- |
| **存储** | 四个集合创建时写死 1024；`init_collections` 只创建、**不重建**；工厂建 store 时不传尺寸 ⇒ 永远 1024（全仓无 `delete_collection`） | `vector_store.py:122` / `:172-181` / `:501-505` |
| **守门** | 工厂四处以 1024 为准；声明了但 ≠1024 直接拒（带"重建索引"提示） | `embedder_factory.py:36` / `:52` / `:137-139` |
| **请求** | 只有 `pins_dimension` 的腿（DashScope / 火山方舟）在请求里带 `dimension=1024`；**通用腿明文"不发 `dimensions` 参数"** | `embedder_factory.py:169-173`、`embedder_openai.py:14-15` / `:95` |
| **声明** | `rag.embedding_dimension` 只做两件事：跳过测量、校验 =1024。**不会**让我们把参数发出去；前端无任何控件（只是文件里的键） | `app_config.py:210`、`embedder_factory.py:173` / `:183`、`frontend/src/core/rag/types.ts:39`（无消费） |

**由现状得出的三条事实**（本 spec 的立论）：

- **F1 · 能用**：模型默认就是 1024，或该腿自带 1024 参数（他当前这条：`rag_config.json` = `dashscope` 原生腿 + `qwen3.7-text-embedding-flash`，`pins_dimension` 注入 1024）⇒ 今天零问题。
- **F2 · 我们主动吃亏**：模型**默认非 1024、但接受 `dimensions` 参数**（Matryoshka 一类：OpenAI `text-embedding-3-*`、Jina v3 系、部分 vLLM 池化模型）⇒ **今天被拒**，尽管它本可满足 1024。**且声明也无解**——声明不改变请求（见上表"声明"行）。
- **F3 · 真无解（乙存在的理由）**：模型**不吃参数、默认又非 1024** ⇒ 今天只能换模型。**乙就是为 F3 开的**：库宽跟模型走，F2/F3 一起解。

### 1.3 三种"探"的形态（整条链的形状由它决定）

| 要什么 | 答案的形态 | 探法 |
| --- | --- | --- |
| **支持哪些维度** | 一个集合；**型别决定它是有穷 / 无穷 / 单点** | **怪值探**定性（`dimensions: 333`，1 发：200=②范围型 / 400=①档位型 / 静默忽略=③固定型）→ **按型走**（①逐档探得完整列表 / ②只验用户输入的那个值 / ③不用探、读默认宽度） |
| **能不能要到某个值** | 是/否 | 选定的值实调一发（保存期探针已在做，扩成三态） |
| **一批能吃多少** | 一个数值上限 | **从高候选起步、撞批量类 400 就沿阶梯降档、首个通过即记**（`20 → 10 → 5 → 2 → 1`）——既是"探上限"又是"保底"（见 D3） |

## 2. 决定

### D1 —— 维度作用域 = **乙 · 部署级维度可配**（**已裁**）

整条链四段，第 ② 段的控件形态**跟着型别走**（1.3 的结论）：

| 段 | 内容 | 形态/落点 |
| --- | --- | --- |
| **① 探** | **怪值探**定性 1 发（`dimensions:333` → 200=范围型 / 400=档位型 / 静默=固定型）；再按型：**档位型逐档探**（内置候选表 `256/512/768/1024/1536/2048/2560/3072/4096`——**表可改**，每值一发，得**完整有效列表**；**候选表只为 ① 跑**——②/③ 不跑表）/ **范围型只验"用户输入的那个值"**（可接受集无穷、枚举不成立）/ **固定型不探**（读默认宽度，一个值） | 新探针端点，探针族规范（真实调用、只读不落盘、有界超时、三态、只报不拦）；结果按 `provider / base_url / model` 绑结论；**三腿同探**（请求构造按 provider 分派，见 §3） |
| **② 呈现** | ① → **输入框（自由填入）+ 框内下拉（档位）**（档位=探到的有效档，保留不可取消）；② → **输入框（数字，任意 ≤ 原生）+ 框内下拉**（静态提示、**只列 ≤ 原生的候选**；**上界由那一发 `dimensions: <原生>` 验过**）；③ → **只读**（显示唯一值）；**档位为空不渲染下拉入口**（理由由框内状态点承载；文案仍说"未探到共识档，请手填"） | 设置页「功能模型」嵌入行的**「维度」**控件（今天该字段无任何界面，只存在于文件） |
| **③ 选** | 单选，**部署级**（四个集合是全局一套，不能按库选）；选定值存进 rag 配置（`embedding_dimension`） | 见 D5-1 |
| **④ 生效/迁移** | 库宽跟所选值走：**新集合名带宽度后缀**（`kb_chunks_{dim}` 等四个）**先建后切**——重建期间运行时**保持旧态**（旧配置 + 旧集合照常可用），全量重嵌完成后才翻配置、之后再删旧集合 | 见 D5-2；重嵌复用 `reindex_kb`（已四路重嵌：切片/实体/wiki/卡片，`reindex.py:1-15`），**新增的是"集合重建"这一前置** |

**为什么不再推荐甲**：甲（只问"能不能要到 1024"、集合仍钉 1024）里"探档位 → 放出来 → 用户选"这条链**没有消费方**（只有 1024 一个可取值）；乙才是他给的形态，且一并解掉 F2（可声明并发参）+ F3（不吃参数的模型也能接）。

### D5 —— 细节（**已按推荐并入**）

| # | 细节 | 已定 |
| --- | --- | --- |
| 1 | **作用域** | **部署级单选**（全局一套集合）。"按库选"= 结构级改造，**不做** |
| 2 | **集合重建的窗口** | **先建后切（无别名依赖）**：新集合用宽度后缀命名（`kb_chunks_1536`），重建期间**运行时保持旧态**（旧集合 + 旧宽度照常读写），四路重嵌完成 ⇒ 翻配置指向新集合 ⇒ 删除旧集合（best-effort）。等价于"别名原子切换"的效果，但不需要 Qdrant 别名 API；失败即中止，旧集合原样可用（可回滚）。对照：`drop/create` 简单但**数据当面销毁、失败得从头再来**，不取 |
| 3 | **现库默认** | 保留 **1024**；**只有显式改值才触发迁移**。现有部署零动作，除非用户去改这个值 |
| 4 | **界面位置**（2026-09-26 追加） | **「高级设置」区块第一行、稀疏来源上面**。理由：① 同类先例——「高级设置」本就是"嵌入腿独有、不与重排配对"的字段的家（`functional-models-view.tsx:335` 注释）；主区那套网格是「提供商 / Model / Key / 地址」两列成对，单腿字段塞进去会留半列空位；② 频率——维度是**选一次长期不动**的部署级字段，主区留给每次配置都会动的四项；③ 计数文案现成（`advancedSettings(N)` 现为 5，加这行 ⇒ 6；`ADVANCED_SETTING_COUNT` `:77` 与用例里的 `advancedLabel(count)` 镜像同步改）。**顺序：维度在上、稀疏来源在下**（维度=库宽、连着迁移，是这块最重的一项） |
| 5 | **连通检测入口 = 两个角色标题 + 状态点**（2026-09-26 追加，他给的设计） | 「向量模型」「重排模型」两个**标题做成按钮**，标题后带一个**状态点**；点击 = 对**该腿**做一次真调用连通测试；悬浮给提示。**四态**：未测=**灰**（hover：为什么灰、点它可以测）/ 检测中=灰+转圈 / **通=绿** / **不通=橙**（hover：真实原因）。**橙是他定的**（仓库现有失败色是 `text-destructive`，此处按裁定用橙——实现可用 Tailwind `amber-*` 或补一个语义 token）。**分工**：标题点 = **连通**（1 发，随手点；**这一发带上所选维度**——同时验"到达 + 凭据 + 这个维度真要得到"）；「高级设置」里维度行 = **能力/档位**（**自动探、无按钮**，见 D5-4 / §3；成本按型：① ≤12、② 3、③ 1，按 key 只发生一次）。**橙色失败要分三种原因**（2026-09-28 加第三）：① 连不上（不可达 / 凭据被拒 / 超时）② **连得上、但所选维度要不到**（模型通了，`dimensions: N` 被拒或被忽略后宽度 ≠ N）③ **连得上、但没给稀疏那一半**（双路 provider 承诺了 sparse 却返回空——`half_missing`；此前被误报成"未能连通"）——hover 分别给"去改端点/钥匙"、"该模型要不到 N 维"+ 可选档位、与"改稀疏来源或换模型"。**点绑 key**（provider / model / base_url / 有无钥匙）——改值即退回灰；结果**会话内、不落盘、不拦保存**。**重排腿一并纳入**（它今天没有任何探针，这是顺手补上的缺口；只加"一发连通测试"，不改它的 URL 构造与请求体）。**数据源已裁（2026-09-26）：只认手动** —— 点的结论只来自"点过的那一发"，**保存期探针的结果不喂给它**（要"保存后自动变绿"是另一档，不做） |
| 6 | **迁移窗口内新入库的文档**（2026-09-27 裁） | **乙 · 结束前扫差量**：迁移开工时记下**每个库的内容签名**（`get_kb_content_stats` 的计数 + 最新编辑时间，外加文档 id 集），**翻配置前再枚举一次**，动过的库**整遍重来**（含还在管线里的文档——切换前它们的写入仍落旧代）。**实现更正（2026-09-27）**：差量以**库**为单位而非逐文档 —— `documents` 表只有 `created_at`（没有 `updated_at`），逐文档判「变过」会漏掉 chunk 编辑；实体/wiki/卡片三路也没有逐文档归属，按库重跑才完整。理由：不挡任何人、丢失面为零；甲（暂停入库）只是把窗口变成"用户被拒"，且在飞/排队文档仍可能落旧代、要严密还得再配差量扫；丙（写入直接进新集合）要给写路径加"迁移中"状态，与 D5-2「运行时保持旧态」冲突 |
| 7 | **迁移跑在哪**（2026-09-27 裁） | **后台任务 + 状态面**：PUT 只做校验并**启动**迁移，**不写新宽度**；四路重嵌全绿（含差量补嵌）后由后台任务**翻配置**（写 `rag_config.json`）；前端轮询进度（复用 `trigger_reindex` 的 fire-and-forget + 轮询形态）。理由：全库重嵌是分钟级，同步 PUT 会撞 nginx/代理默认 60s 超时与浏览器长等待；失败即中止 ⇒ 文件从未写过新宽度 ⇒ 旧集合/旧配置原样可用（回滚＝什么都没发生） |

### D2 —— 乙档下"维度参数怎么生效"（**已裁：甲a**，2026-09-26）

> 裁定 = 甲a：**声明了就发 `dimensions: N`**；其表内的"自愈兜底"（400 ⇒ 去参重试同一批一次、进程内记住）**一并保留** —— 它只兜"严格端点对未知参数回 400"这一种噪音，不改主语义。

| | **甲a · 声明为准 + 自愈兜底**（推荐） | 甲b · 只靠运行时自愈 | 甲c · 探针定判 + 落盘能力位 |
| --- | --- | --- | --- |
| 做法 | 选定值（= `embedding_dimension`）**就发** `dimensions: N`；万一运行时仍被拒（400）⇒ **去掉参数重试同一批一次**、进程内记住该 key"别带参" | 首调不带参、量到 ≠ 目标才带参重试 | 探针判定"接受参数"后把**能力位落盘**，运行时按位发参 |
| 优点 | 语义直白（选了什么就发什么）；**运行时不依赖任何持久化能力位**；厂商腿（`pins_dimension`）语义不变 | 用户零输入 | 跨重启一致 |
| 代价 | 首调可能 +1 发（仅当端点对未知参数回 400；保存期探针若已通过，实际很少触发） | 每次新进程重演；"选了的参数"在首调不生效 | 用户文件出现服务器派生的状态（与"文件只存用户声明"冲突） |
| 兜底靠什么 | **保存期探针**（`rag_config.py:349-373`）实测返回宽度：模型忽略/拒绝所选的 N ⇒ **拒绝保存**并给可执行文案 | 同左 | 同左 |

**收口**：保存期探针是"选的值真能生效吗"的**唯一关口**；运行期的自愈只兜"严格端点对未知参数回 400"这一种噪音。

### D3 —— 批量落法 = **甲′（运行时自探上限）**（**已裁**，2026-09-26）

裁定形态（他给的）：**从最高候选起步、沿阶梯降档、首个通过即用**（`20 → 10 → 5 → 2 → 1`）。

| 件 | 内容 |
| --- | --- |
| **阶梯** | 常量 `[20, 10, 5, 2, 1]`（**可改；顶端 20 只是"有实测证据的最高档"，往上加档是自由的**）；**降档 = 取下一档**（不是数学减半——避免 2.5 这种）。起点 20 = **有实测证据的最高档**（`qwen3.7-text-embedding` 20 行 200，`embedder.py:51`）；10 = 已知最低安全值（`embedder_openai.py:45`） |
| **初值（必改）** | **通用腿的 `batch_size` 属性初值 = 20**（阶梯顶端）。`index_chunks` 按 `embedder.batch_size` 先切片（`indexer.py:66-68`），属性初值若还是 10 ⇒ **20 那一档永远发不出去**、阶梯退化成 `[10,5,2,1]`；`DEFAULT_BATCH_LIMIT`（值 10）继续只服务稀疏腿 |
| **触发** | 某批撞**批量类 400** ⇒ 降一档重试**同一批**；成功 ⇒ 记住该 `(provider, url, model)` 的当前档，**后续所有批直接用它**（进程内，D4=甲） |

## 4. 验收

1. **探测三型可分且自动**：对三种桩/真服务，探针分别报 `tiered`（列出有效档）/ `range`（报原生宽度）/ `fixed`（报唯一值）；**三条嵌入腿各一遍**（桩按各自的请求形状校验请求体：通用腿 `dimensions` / dashscope `parameters.dimension` / ark 一次一条）；**候选表只为 ① 跑**（②/③ 型的桩上**看不到候选表请求**——② = 定性 + 量宽 + 上界验证 **3 发**，③ 只有定性 1 发）；**改 provider / Model / 地址后自动跑**（防抖、**无需点按钮**、同 key 不重探）；只报不拦、不落盘。
2. **呈现（三型统一形态）**：**输入框 + 框内下拉**——① 的下拉＝探到的列表（点一下填进输入框、**不可取消**）；② 只给静态档位提示（**不跑候选表**——它仍有定性 / 量宽 / 上界那 3 发；**选项取自探针响应的 `candidates` 且只列 ≤ 原生的那些**，超原生的不列/置灰，前端不另抄）；③ 输入框只读、无下拉入口；**档位为空不渲染下拉入口**（显示"未探到共识档，请手填"）；**0 档回退**：① 型一档都没探到 ⇒ 显示默认宽度 + 可手填 + 说明句（桩：任何参数都 400 的严格端点）。（dom 用例钉结构，几何归真浏览器）；探完之前不阻塞保存、状态骑在行内。
3. **选择生效**：选定 N ⇒ 请求体确带 `dimensions: N`（请求断言，非"结果碰巧对"）；厂商腿（`pins_dimension`）行为不变。
4. **保存期三态**：模型忽略所选值（返回宽度 ≠ N）⇒ 保存被 **400** 拒并给"该值要不到"的可执行文案；能要到 ⇒ 通过；**判定跟生效宽度**——选 1536 时不再按 1024 判（`rag_config.py:370-372` 与 `dimension_mismatch_message` 已改）。
5. **迁移**：改 N ⇒ 新集合按 N 建、**遍历所有库**四路重嵌完成后配置才翻；**迁移失败时旧集合与旧配置原样可用**（回滚证据）；完成后旧集合被清掉；**迁移期间新入库的文档不丢**（按选定的处理方式给证据）；**中断后重试不撞残留**（按选定的"先删后建"给证据）。
6. **零迁移默认**：不动维度时，现有部署（含他当前 dashscope 原生腿）的行为与请求**逐字节不变**；既有断言零改动全绿。
7. **批量（D3=甲′）**：**首批就是 20 行**（属性初值=阶梯顶端，桩计数断言）⇒ 撞 400 后沿阶梯降到 5 通过同一批（**该批不落 failed**）；此后同进程的批直接按 5 发（请求行数断言）；上限 20 的桩 ⇒ 首批即通过、此后按 20 发。
8. **空地址/必填不变**：空地址仍拒（09-25 语义），既有用例零改。
9. **门禁**：后端相关面 + `make lint`；前端 `pnpm check` + 相关 dom 用例；真栈用本机桩（零出网）跑 1 / 3 / 5 / 7。
10. **连通点四态（D5-5）**：桩下点「向量模型」「重排模型」两个标题按钮 ⇒ 未测=灰、检测中=转圈、通=**绿**、不通=**橙**；**橙分两种原因**（`refused`/`unreachable` ⇒ 连不上；**`dimension_unavailable`** ⇒ 连得上但所选维度要不到），hover 分别给"改端点或钥匙"与"要不到 N 维 + 可选档位"；那发**带所选维度**（桩按"只收 1024"实现 ⇒ 选 1536 时报第二种原因）；改任一进 key 的值 ⇒ 退回灰；缺必填 ⇒ 灰且禁用（hover 说明缺什么）；**任何态都不拦保存**。
11. **非目标零触碰**：rerank / parse / 稀疏腿的 **URL 构造与请求体**零改动（重排腿新增的只是"一发连通测试"，是新增、不是改动）；检索路径的三路逻辑零改动；`config.yaml` 不被 PUT 写入；**`DEFAULT_BATCH_LIMIT` 的值不变**（稀疏腿共用它）。
12. **维度字段往返 + 迁移触发判据**：设 1024/1536 ⇒ 保存 ⇒ GET 返回的仍是该值；随后一次**无关编辑**（如改 `qdrant_url`）保存后它**仍在**（今天会被 `buildRagConfigInput` 的字段清单漏掉而抹除）；**填与当前生效宽度相同的值 ⇒ 不触发迁移**（无论它是点档位还是手填）。
13. **原生宽度的补验（verify-then-list）**：① 型桩的原生宽度**不在候选表内** ⇒ 能观察到那一发补验（带 `dimensions: <原生>`）；通过 ⇒ 它出现在档位列表里，不通过 ⇒ 不出现；原生在表内 ⇒ **不补发**（逐档探已问过）。
14. **② 的上界验证与判歪降级**：② 型桩 ⇒ **恒观察到一发 `dimensions: <原生>`** 且通过（上界可用被证明）；**"假 ②"的常见分支**（真 ① 收 333、且原生可设）⇒ 那一发**通过** ⇒ **不降级**（档位区退化为未验提示 + 保存期兜底）；**罕见分支**（原生不在它的集合里）⇒ 那一发失败 ⇒ 探针**当场降级跑候选表**、`values` 变成该模型的真档位；③ 型桩 ⇒ **没有**这一发。
15. **钳位桩（状态码撒谎）**：桩对某候选值回 **`200` 但宽度 ≠ 所求**（复刻 `flash` 的 1536⇒1024）⇒ 该值**不列**；① 逐档、① 原生补验、② 上界**三处都按"宽度相等"判**（只看状态码的实现会被这条用例打红）。

## 5. 影响面与非目标

- **影响面**：通用嵌入腿的请求构造 + 集合命名与生命周期 + 保存期探针 + 设置页嵌入行 + **两腿各加一个"连通检测"入口（D5-5，含重排腿——它今天没有任何探针）**；**厂商腿（dashscope / ark）的入库请求零改动**——它们的宽度照旧由工厂注入（`pins_dimension`），本对新增的只是**探测路径**（探测会按各家形状真发请求，但那是探针自己的请求，不是入库路径的改动）；重排腿的**既有行为零改动**（新增的只是那发连通调用）。
- **非目标**：Per-KB 维度（结构级改造）· 换协议/新参数（只做 `dimensions` 这一个标准参数）· rerank/parse/稀疏腿的批量（`sparse.py:104` 今天也固定 10）· 自动改写用户配置（探针只回答，不改值）· 迁移期的双写/在线零停顿（接受"运行时保持旧态、切点后新态"）。
- **存量账**：现有集合（无后缀）在首次迁移时按 `size=1024` 对待；不迁移就完全不碰。
