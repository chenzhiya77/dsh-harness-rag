# 面板 · 文档表交互收口（列头溢出＋行拖拽） —— spec

**Status:** 立项（2026-10-21，**D1–D4 已拍：全甲**；未开工、未提交）。
**Date:** 2026-10-21
**来源:** 10-21 他两点体验问题——①上传者列头的列选项控件被时间列截断；②文档行不能拖动排序，且与排序按钮的关系待定；随后令「落盘，先写 spec 和 plan」。
**承接:** 列头为 [2026-10-16-doc-columns-spec.md](2026-10-16-doc-columns-spec.md)「定宽改造」带出的回归；拖拽为插件自有能力（工作台文档表无此功能），非照抄项。
**配套 plan:** [../plans/2026-10-21-doc-table-interactions-plan.md](../plans/2026-10-21-doc-table-interactions-plan.md)

## 1. 范围

本对两件（落点全在 `client.js` 文档段；host 半与后端预期零改）：

1. **列头溢出修**：上传者、切片数两个短列的表头 chevron 被相邻列盖住／截断；按「标签＋间距＋chevron＋内衬」把定宽配足，恢复可点。
2. **文档行拖拽排序**：行可拖动改位；与既有排序菜单的关系、手动顺序的持久化、跨刷新／切库／新上传／搜索／多选的边界一并定口径。

**不包含**：后端排序字段或顺序持久化；工作台文档表同步加拖拽；其他 tab 的排序；排序键本身的增删。

## 2. 现状与根因（10-21 只读核实）

### 2.1 列头为什么会被时间列截断

- 表格是 `table-layout: fixed`＋定宽列（`client.js:1931`）；上传者列 `52px`（`client.js:1940`），扣左右各 8px 内衬只剩 **36px**。
- 表头内容＝标签＋`gap:2px`＋`18px` chevron（`client.js:1934` / `client.js:1970`）；「上传者」3 个汉字在 12px 下正好约 36px，加间距与 chevron 共约 **56px**，溢出 20px。
- 所有 `th` 都是 `position:sticky; z-index:10` 且带不透明底色（`client.js:1933`）；同层级后绘制的「时间」列把前一列溢出的 chevron 盖住，视觉上就是被截断。
- 切片数 `56px`（`client.js:1944`）是第二个 3 字列，同样溢出；状态（80px）、时间（124px）、大小（74px）均有富余。
- 工作台列宽随内容自然增长（自动布局，`frontend/src/components/workspace/knowledge/document-panel.tsx:778`），所以同样形态不会截断。10-16 改定宽是为解决名称列 min-content 撑破面板，方向本身不回退。
- 既有 spec/plan 与工作记录中没有这条的登记；当前代码也没有任何补偿，属未修回归。

### 2.2 文档行为什么还不能拖

- 排序只有四个字段键（`client.js:8104-8110`），可见集＝过滤后直接 `docsSort`（`client.js:8656-8657`），没有「手动顺序」这一态。
- 排序状态是组件内会话态（`client.js:8567`），重挂载回到默认 `created_at desc`；没有任何顺序存储。
- 文档表行本身无 `draggable`（行元素 `client.js:9045-9060`），工作台文档表也没有拖拽实现（`document-panel.tsx` 全文无 `draggable`／DnD）。
- 可复用的同族先例是库下拉的拖拽重排（`client.js:17621-17680`：HTML5 DnD＋窗口级 dragover 委托＋`hrag-kb-order` 持久化），本对只在行表上重写同口径，不搬菜单件。
- 既有 spec/plan 与工作记录中没有「文档拖拽」的登记；不是已做未生效，是从未实现。

## 3. 决策表（D1–D4，**10-21 全甲拍定**）

### D1 —— 列头溢出修法（**已拍：甲**，2026-10-21）

- **甲（拍定）**：定宽把控件算进去——上传者 `52→68~72px`、切片数 `56→72px`；chevron 向工作台看齐缩到 14~16px、间距 0~2px；`min-width:552` 同步加 20~32px，名称列让位。最终数值以 Task 0 真浏览器量「标签实际宽＋chevron 盒＋内衬」后钉死。
- **Task 0 钉值（2026-10-21，他拍「按建议」）**：上传者／切片数均 **72px**、chevron 盒 **16px**（内层 svg 14）、gap **2px**；**`min-width` 维持 552**（加 36 会在 570 档造 18px 横滚，余量改由名称列吸收：570 档名称内容 68、552 档 50）；en 界面 `Uploader`／`Chunks` 仍按现状截断（配足需 88／78 或改词，本对不收）。
- **紧凑档（10-21 补，他令「只先做紧凑档」→「680 断点台阶改平滑」）**：短列常驻 **68px**（chevron 盒 14／内层 svg 12、gap 0）；时间列改连续 `clamp`——绝对 `clamp(120px, calc(102.75px + 3.125cqw), 124px)`、相对 `clamp(72px, calc(3px + 12.5cqw), 88px)`，552→680 之间随容器宽连续收放，两端封顶。状态 80／大小 74 已贴数据硬下限不动。名称内容宽：570 档 **79.4**（绝对）／**125.8**（相对），740 档 **246／282**；679／680／681 三档名称宽 185.0／186／187（无台阶），552–1000 零横滚。
- 乙：短列不渲染 chevron，只留表头右键＋「列」总控。
- 丙：表格退回自动布局（工作台同款）。
- 判据：甲保留工作台同款可发现性与逐列入口；乙入口不一致；丙会重现 10-16 已裁的名称列撑破／横滚问题。另可加 `th:hover{z-index:11}` 作兜底，但不作为主修（不解决空间不足）。

### D2 —— 拖拽与排序按钮的关系（**已拍：甲**，2026-10-21）

- **甲（拍定）**：拖动即切「手动排序」并**即时生效＋持久化**；排序菜单的勾同步切到「手动排序」。点任一字段排序立即退出该模式并重排，但保留手动顺序；再选「手动排序」恢复。手动模式下方方向项隐藏或置灰。
- 乙：显式门——必须先选「手动排序」才允许拖。
- 丙：拖动只改视觉，下次点排序按钮才提交（他提的候选）。
- 判据：甲让屏幕顺序与排序状态始终一致；乙多一步、可发现性差；丙会出现「看到的是手动序、状态却写着字段序」的隐藏态，刷新还可能跳回，不采用。

### D3 —— 手动顺序的持久化与合并（**已拍：甲**，2026-10-21）

- **甲（拍定）**：`hrag-doc-order.{kbId}` 存 `{ mode, ids }`；按 id 合并——仍存在的按保存序，已删的剔除，新文档按默认序排**末尾**；切库／切 tab／重开都恢复 mode＋order。
- 乙：只存 ids，mode 保持会话态。
- 丙：新文档插到**顶部**（更显眼，但会打断用户已排好的顺序）。
- 判据：甲不会出现「顺序存了但模式没存、重开看似丢序」；丙更适合「只看最新」的库，作为可拍选项保留。

### D4 —— 拖拽入口与禁用条件（**已拍：甲**，2026-10-21）

- **甲（拍定）**：整行可拖（`draggable`；checkbox／行内按钮／菜单触发器排除），悬停 `cursor: grab`，落点画插入线；搜索词非空或多选时禁用拖动；拖动期间暂停 3s 轮询。
- 乙：行首 hover 出现 grip handle（需挤占复选列或名称列）。
- 丙：仅名称单元格可拖（库下拉同款，可发现性靠 cursor）。
- 判据：甲零布局改动、拖拽目标明确；乙多一枚控件但可发现性最好，代价是挤宽度；丙最省但「拖名字」与「拖行」体感不一致。

## 4. 口径（D1–D4 甲已定；数值待 Task 0 钉死）

### 4.1 列宽

- 每个可隐藏列表头预留「标签全文＋2px 间距＋chevron 盒＋左右 16px 内衬」；chevron 常驻占位、仅 opacity 变化，悬停不引起列宽跳动。
- 上传者／切片数按 3 字列配足；名称列吃剩余宽度，超宽省略号规则不变；`min-width` 维持 552（横滚阈值不变）。
- 窄栏缓冲：短列 68、时间列按容器宽 `clamp` 连续收放（绝对 120→124、相对 72→88，552→680），缩窄由时间列与名称列共同承担，无断点台阶。
- 列宽按中文标签钉死；en 的 `Uploader`（52.98px）／`Chunks`（42.3px）超出 72 列内容宽，维持现状截断（既有差异，登记不做）。
- 不改变列集合、默认显隐、时间格式／大小单位、表头右键与「列」总控的行为。

### 4.2 排序模式

| 场景 | 结果 |
| --- | --- |
| 初始／从未拖过 | `created_at desc`；排序菜单勾「上传时间」＋「降序」 |
| 拖动任一行 | 立即切「手动排序」；以当前可见全集顺序为基，落点生效并写入；菜单勾「手动排序」，方向项置灰 |
| 手动模式下继续拖 | 覆盖同一份手动顺序，不新增第二套 |
| 选任一字段排序 | 立即按该字段重排；手动顺序保留；方向项恢复可用 |
| 再选「手动排序」 | 恢复上次保存的顺序；新文档按 D3 规则处理 |
| 搜索词非空 | 仍可按手动顺序显示，但拖动禁用（避免只对子集排序的歧义） |
| 多选非空 | 拖动禁用；批量动作不受影响 |
| 拖动中遇 3s 轮询 | 暂停／排队该次刷新，落点后再合并，避免行序跳动 |
| 切库 | 读该库自己的 mode＋order；无键＝默认字段排序 |
| 切 tab／重挂载 | mode＋order 从本地恢复，不回到默认排序 |
| 删除文档 | 下次读写时剔除失效 id；不影响其余相对顺序 |

### 4.3 存储

- 键族沿用插件既有 per-kb 先例（`hrag-doc-table-prefs.{kbId}`，`client.js:8238-8276`）：`hrag-doc-order.{kbId}`。
- 值：`{ mode: 'manual' | 'created_at' | 'name' | 'size_bytes' | 'chunk_count', ids: string[] }`；方向仍随字段模式走，手动模式不存方向。
- 脏数据／缺失一律回退默认（本地 UI 偏好永不崩）；只存 id 数组，不存行快照。

### 4.4 拖拽反馈

- 整行作为拖拽源；按下落在 checkbox、⋯、列菜单、链接等交互件上时不启动拖拽。
- 落点行显示 2px 插入线（上／下半区判定前后）；被拖行降透明度；drop 后立即重排并保存。
- 点击仍打开切片抽屉；拖拽结束后的 click 抑制由 HTML5 DnD 原生行为保证，另加一次 guard 兜底。
- 无后端请求；顺序纯本地。

## 5. 验收

1. **列头**：面板 570／740／满宽三档，逐个悬停全部可隐藏列表头——chevron 完整可见、可点开菜单；任何列不被相邻列盖住；悬停不引起列宽跳动；名称列仍按既有规则省略。
2. **基本拖拽**：拖动一行到新位置立即生效，排序菜单同步勾「手动排序」；重开面板／切 tab／切库回来顺序保持。
3. **排序往返**：字段排序 → 点「手动排序」恢复上次顺序；手动模式方向项不可用；再次拖动覆盖旧手动序。
4. **增删**：手动模式下新上传文档排末尾，既有相对顺序不变；删除后失效 id 不影响其余顺序。
5. **边界**：搜索词非空、多选非空时不可拖；3s 轮询不打断拖动、不把行序跳回；行点击开抽屉、复选框、右键菜单、批量删除均不受影响。
6. **门禁**：`node --check client.js`；`src/*.ts` strip-types 全过；冒烟默认与 `SMOKE_HOSTLESS=1` 全绿；DSH 整重启后真跑（候令）；deer-flow 主树与后端零改动。

## 6. 影响面

**改的（插件仓）**：`client.js`（表头定宽／chevron／排序模式／存储助手／行 DnD）＋内联 zh/en 文案；本对 spec／plan；收口时 `docs/equivalence.md` 登记「文档行拖拽＝插件自有、工作台无此能力」。

**不改的**：后端与 API 形状；工作台（deer-flow）全部；host 半（`src/*.ts` 预期零改）；列偏好、行菜单、批量、上传链。

**并行工作区**：`src/model_sync.ts`、`tests/model_sync.test.ts` 与 `2026-10-21-dsh-model-proxy-*` 两文档为他线未提交改动，本对不触碰、不纳入提交。

## 7. 不做

- 不做服务端顺序持久化／多端同步（本地 UI 偏好，跨客户端不共享）。
- 不做搜索子集内拖拽、多行整体拖动、键盘上移／下移（v1 登记候选）。
- 不给工作台补拖拽，不对齐成上游能力。
- 不改字段排序的键集合、方向语义与默认值。
- 不重做列偏好、表头右键、「列」总控、行菜单与批量选择。
