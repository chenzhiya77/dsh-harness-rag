# DeepDuck · Harness RAG

> **DeepSeek Harness（DSH）插件**：一套**内置本地知识库（Harness RAG）**——从文档 / 表格 / 视频的解析与切分，到实体图谱、百科条目、三路检索、文档感知（枚举 / 定位 / 读回）、知识库管理与检索质量评测。
>
> **为什么是 Harness RAG**：检索不是一条固定流水线——三路各司其职：向量负责内容匹配、图谱负责信息关系、百科负责条目级线索；库里的文档与百科条目可以直接枚举，不拿检索硬凑。命中切片随工具结果返回；绑定知识库的会话还会收到一段检索纪律（向量保底 / 图谱路 / 读取上限 / 引用照抄 / 拒答），人格与呈现仍归宿主。
>
> 本仓库是 **DSH 插件**：Host 半注册模型可见工具与面板数据桥，Client 半注册右栏「知识库」tab；默认自带本地知识服务（便携 Python、Qdrant、引擎），`backendUrl` 非空时走外部服务。

## 🧩 插件由什么组成

### DSH 插件（host 半 + client 半）

Host 半在宿主世界注册 `hrag_*` 工具、面板数据桥与摄取后台任务，并负责运行时的准备、启动与守护；Client 半在浏览器世界注册右栏「知识库」tab（完整面板）。两半各自声明依赖，不能互吃对面世界的服务。

### Harness RAG（内置引擎）

解析、切片、嵌入、索引、图谱、wiki、评测与存储全部在 knowledge 服务侧。默认由插件托管：运行时落在 `<root>/runtime/<version>/`（便携 Python、site-packages、engine 源码、Qdrant），数据落在 `<root>/state/`；`backendUrl` 非空时完全走外部服务，不下载、不起进程。

**访问与安全边界**

- **工具按会话挂载**：六件 `hrag_*` 只在会话绑定知识库后挂进该会话；解绑即从该会话的工具表消失，未绑定的会话没有这些工具。
- **agent 只读**：不存在 agent 侧的写入工具——上传、删除、触发解析、生成百科都是人类操作。
- **数据在本机**：托管模式的数据与 token 落在运行根（`state/`），面板不显示 token；外部模式用 `apiToken` 保护知识服务。
- **命名空间隔离**：工具名 `hrag_*`、槽位标识 `dsh-harness-rag` / `harness-rag`、localStorage `hrag-*`、代理路由 `/dsh-harness-rag/api`，与其他插件零冲突面。

## 🔍 Harness RAG 提供什么

### 摄取与解析

- **经 MinerU 解析**：`.pdf`、`.doc` / `.docx`、`.ppt` / `.pptx`、`.png` / `.jpg` / `.jpeg`。文档内的表格会归一为 GFM 表格；正文中抽出的图片由 VLM 生成说明，并保留在原文档位置就地渲染
- **本地直读**（不走网络）：`.md` / `.markdown` / `.txt`
- **表格**：`.csv` 始终可用；`.xlsx` / `.xls` / `.tsv` 由 `rag.table.enabled` 门控。统一归一为 GFM 表格——Excel 逐 sheet 一张表，`.csv` / `.tsv` 按分隔符解析；`.xlsx` 内嵌图片一并抽出（挂到锚点单元格、越界回退该 sheet 段尾），经 VLM 配文后随切片渲染
- **视频**：`.mp4` / `.mov` / `.mkv` / `.webm`，由 `rag.video.enabled` 门控。**ASR 默认在本地运行**（funasr / Paraformer，可切 whisper，均为进程内引擎、不依赖外部推理服务），也可改用转录服务档（`openai-audio` / `dashscope`）——服务档只处理 ≤5 分钟音频、更长自动回落本地引擎；镜头画面说明、关键帧屏幕文字与向量化走所配置的模型端点。ASR + 关键帧 + 分镜卡，产物以切片形式进入同一套检索。托管运行时**不含本地视频 ASR 依赖**（funasr / torch）：视频默认档需另装，或在功能模型设置里改用 ASR 服务档
- **解析可接自建服务**：`rag.parse_provider` 默认 `mineru-cloud`（MinerU 官方 API）；改成 `mineru-local` 并填 `rag.parse_base_url` 即接**自建的 MinerU 服务**（对接上游 4.x 的 HTTP 契约，本仓按 4.0.7 验证：上传 → 建解析任务 → 轮询 → 取结果 zip；轻客户端形态，本机不跑模型推理；该服务本身不带鉴权，只应部署在内网）。**该地址云腿同样生效**：留空＝官方地址，填了就打到它。`rag.parse_tier` 可选 `flash` / `basic` / `standard` / `advanced` 指定解析档位，留空则由服务端决定（服务端自身默认 `standard`；`standard` / `advanced` 需要服务端装 torch）；云腿另有 `rag.parse_language`（文档语言包，缺省 `ch`，覆盖中英文）与 `rag.parse_model_version`（模型版本 `pipeline` / `vlm`，缺省 `vlm`）两个旋钮。换解析来源不影响表格归一化、图片落盘与就地渲染

全部开启时共支持 19 种后缀。

### 加工

- **结构感知切分**：`heading_path` 等结构元数据随切片落库；表格按表头锚定行组，一张表拆成多张卡片时每张都自带表头
- **归一化（两把尺子）**：别名表（大小写 / 空白折叠、英文复数折叠、「中文（English）」括号折叠）+ 嵌入相似度阈值；簇的代表名优先取括号全名
- **跨片重解析（五步幂等链）**：合并实体行 → 重写关系端点（去重、去自环）→ 删别名向量并按合并后的描述重嵌代表 → 双写切片标签（业务库列 + Qdrant payload）→ 相关百科条目标脏
- **Wiki 百科生成**：资格 = 卫生门槛 + 跨 ≥2 切片；物料打包（源切片重叠 Jaccard ≥ 0.5、≤7 个一组，一次 LLM 产出多个条目）→ 脏条目增量重生成，并回填新合格条目
- **不变量**：单腿失败不阻塞文档到达 ready；管线在飞时并发重抽 / 删除返回 409；重排故障降级为 RRF 序

### 全链路联动（改动 → 下游传播）

知识入库后不是静态的——上游任何改动都会沿图谱与百科向下传导：

| 上游动作 | 下游传播 |
| --- | --- |
| 编辑切片 | 就地重嵌入；实体保持不变——需重新理解内容时显式「重抽」 |
| 重抽切片 | 撤旧抽取 → 清孤实体 → 按当前文本重抽（不重解析源文件）→ 归一化 → 合格实体标脏 |
| 删除切片 | 级联：图谱贡献 → 孤实体向量 → 百科失格链 → 向量点 → 业务行 |
| 新增文档 | 图谱腿重解析触达实体 → 相关条目标脏 → 增量重生成（并回填新合格条目） |
| 删除文档 | 三存储级联（向量 → 图谱 → 百科生命周期 → 业务行）；高频实体标脏、跌阈实体失格 |

**全链路双向联通**：写侧改动向下传导（上表）；读侧沿同一条链上行——枚举文档与百科条目、按篇 / 按片读回原文，并可按实体名 / 条目名直取图谱与百科（见「文档感知」）。

### 检索（三路）

- `hrag_hybrid_search`：**内容匹配**——混合召回（dense + sparse 单次调用）→ RRF 融合 → 重排；结果带 `chunk_id` / `doc_id` / `chunk_index` / 实体与 `citation_no`，可按 `doc_id` 限定单篇；重排服务故障自动降级为 RRF 序
- `hrag_graph_search`：**信息关系**——按问题理解或 `entity` 精确实体直取，1–2 跳扩展；证据片带 `doc_id` 与 `citation_no`
- `hrag_wiki_search`：**条目级线索**——返回百科条目或人工知识卡的完整正文；可按 `title` 精确直取，含用户自建的「我的条目」
- 引用编号：引擎按会话回合分配连续 `citation_no`，三路工具共用一套编号；绑定会话同时获得检索纪律（向量保底 / 图谱路 / 语料边界 / 读取上限 / 引用照抄 / 拒答），人格与呈现仍由宿主决定。

### 文档感知（只读）

库里的文档与百科条目不再只能靠检索「碰见」——三件只读工具把它们变成可直接使用的对象：文档**能枚举、能定位、能读回**，百科条目**能枚举**。它们不是旁路：整条链本来就是通的（解析 → 切分 → 落库 → 图谱 / 百科），文档与切片的关系、切片的顺序与位置早已在其中，三件工具只是把既有关系以只读方式开放给 agent；与三路检索共用同一条知识库绑定。

- `hrag_list_documents`：**文档清单**——`doc_id` / 名称 / 状态 / 切片数，附就绪 / 处理中 / 失败计数
- `hrag_read_document`：**原文读取**——`doc_id` + offset/limit 分页通读整篇；或只给 `chunk_id`，直接读该片为中心、边界收拢的窗口。单条超 2000 字截断并标 `truncated`，每片附实体（去重后最多 10 个）。
- `hrag_list_wiki_entries`：**百科条目清单**——标题 / 状态 / 更新时间与就绪 / 待更新的诚实计数；只含过门槛的生成条目，未达门槛的实体由图谱与向量两路直接服务
- 追问链：切片级命中自带 `chunk_id`（向量、图谱两路），`hrag_read_document` 可直接以 `chunk_id` 续读；图谱证据另带 `doc_id`，也可按篇分页。
- 错误面：不存在 / 跨库 / 未就绪的读取请求以 200 + 可读 message 返回（工具级拒绝不抛 404）。
- 与引用两分：事实性结论仍走三路检索并标 `[n]`；枚举 / 结构 / 定位类回答以文字出处（文档名 / 片序 / 条目名）作答——清单与读取不进编号体系

### 知识库面板（右栏 tab）

面板顶栏＝库选择器 + 「会话」绑定入口 + ⋯ 菜单；六个分区 tab＝文档 / 图谱 / Wiki / 召回 / 投影 / 评测。文档表支持本地文件夹分组（新建 / 改名 / 折叠 / 移动 / 删除，per-kb localStorage），切片抽屉限位在面板内；面板可拖宽、分栏、全屏或浮动，窄面板下 tab 条尾部折叠为下拉菜单；界面中英双语。面板不内置对话：与知识库绑定的会话直接用 DSH 对话 + `hrag_*` 工具。

### 全链路可视化

从摄取到评测，**每一层加工都有对应的可视化入口**：

| 链路层 | 看什么 |
| --- | --- |
| 摄取 / 解析 | 文档表：逐路径解析状态（向量 / 图谱 / 百科三条腿；视频文档另有「语音 / 分镜 / 配文」三条预处理腿），失败可就地重试 |
| 切分 | 切片抽屉：tick 轨 + 卡片列表；表格类文档转出的 GFM 表切片自带表头 |
| 归一化 / 实体图谱 | 知识图谱：力导向图、社区层上卷、悬停高亮一跳邻居 |
| Wiki 百科 | 百科（Wiki）tab：「生成条目」与「我的条目」两区，条目抽屉回看源切片 |
| 三路检索 | 召回：一条查询的三路命中并列（含跨路耗时排名） |
| 向量空间 | 投影：切片 / 实体 / 百科 / 条目四类点的 2D / 3D 投影 |
| 评测 | 题库、指标总览、趋势图 |
| 检索轮次 | 命中实时叠加到向量空间与知识图谱（见「特别设计」） |

### 特别设计

- **检索叠加可视化**：召回或检索测试的每一轮命中，实时叠加到**向量空间**（命中点与查询点落图）与**知识图谱**（种子 / 扩展 / 证据三层染色 + 邻居高亮）；叠加以增量方式更新，**不重排布局**
- **百科全链路可维护、且可定向**：任何上游改动经脏链增量重生成；条目编辑内容会作为下一次生成的「方向」；生成粒度可选增量 / 全量 / 按条目

### 质量闭环

- **两层评测**：Layer-1 为确定性 IR 指标（命中率 / 召回@k / MRR / 路径准确率，可复现）；Layer-2 为 LLM 评分（含 RAGAS 的忠实度、答案相关性、引用精度等）
- **题目可自动生成**：选一篇或多篇文档**联合出题**，一次产出 1–10 道候选（默认 5 道），必须逐条**采纳 / 忽略**后才进题库（入库先过锚定核验，锚不对会被拦下、确认后才入库；锚可事后修正，悬空 / 存疑直接标在题库里）；也可手工添加
- **门禁分工**：Layer-1 可复现，适合当回归判据；Layer-2 只出报告、**不设门禁**（避免 judge 方差把回归判定带偏）
- **运行可见**：三阶段进度（检索评测 / 答题评测 / 质量评估）并可中止；趋势图按运行序数出图，缺一次运行不会把两个时段压成相邻点

### 模型配置（来自 DSH）

- **聊天模型**：由 DSH 当前可用的模型发布而来。插件在宿主机起一个 OpenAI 兼容代理（`/dsh-harness-rag/llm/v1`），引擎为每个 DSH 模型只保存一条指向该代理的别名（`dsh:<provider>/<model>`）；provider 的 endpoint 与 key 留在 DSH 内。DSH 停止时别名调用返回可读错误；模型目录变化或插件激活时自动同步；功能模型是全局作用域
- **RAG 功能模型**：图谱抽取 / 评测裁判 / 说明生成 VLM / 百科生成 / 考题合成等角色从 DSH 模型中选择；面板 ⋯ →「功能模型设置」按角色分组编辑，另含嵌入、重排、ASR、Qdrant / MinerU 设置。每个角色可选思考档位（关 / 跟随 / 六档），不选即跟随 DSH 默认
- **三条外部依赖可选 provider**（与上面的聊天模型机制**互不相通**——不共享条目，也不继承其支持面）：嵌入可走百炼或火山方舟原生接口（两家都出稠密 + 稀疏），或任一 OpenAI 兼容的 `/v1/embeddings`（仅稠密）；重排可走百炼，或通用 `/rerank`（Cohere / Jina 形状），或自建 Text Embeddings Inference 的 `/rerank`；解析可走云，或自建的 MinerU 服务（上游 4.x，解析档位由 `rag.parse_tier` 指定，留空 = 服务端定）。**嵌入宽度是部署设置**（`rag.embedding_dimension`，留空 = 1024）：模型返回宽度与生效宽度不符会被拒绝启用；改宽度触发全库重建的维度迁移（入口：面板 ⋯ →「功能模型设置」→ 高级设置 → 维度）。**每库另落一枚嵌入身份章**（provider / Model / 地址的指纹；全库重建完成或库内首篇处理完成时写下）：换提供商 / 模型 / 地址后，与章不符会被检索侧检出并提示——不拒查询，混用可查、质量无从保证；重建完成即重新落章。
- **稀疏来源三选一**（`rag.embedding_sparse_source`）：随嵌入模型同出（百炼）、另配一个专门的稀疏服务（`tei-sparse`，对接 Text Embeddings Inference 的 `/embed_sparse`）、或本地 BM25（零模型、确定性最好，中文按字符二元切分）。换成只出稠密向量的嵌入模型后，必须选后两者之一
- **外部依赖可就地体检**：向量 / 重排两条腿的标题可点出发起连通检测（连通正常 / 无法连通 / 无法提供所选维度）；维度在改提供商 / Model / 地址后自动探测模型支持的档位与原生宽度，无需手动发起；稀疏能力在选「跟随向量模型」时自动发一次真实只读嵌入调用验证，明确不支持会拦住保存；独立稀疏服务的地址栏内报告「连不上 / 没返回词项」（只报告、不拦）
- **重建索引**：「功能模型设置 → 重建索引」按库重新嵌入**全部向量**——切片、实体、百科条目与人工卡片一起换到新的向量空间。它只重嵌入、**不重解析**源文件，也**不重跑图谱抽取**——所以换 provider / 换维度之后原文件不在也照样能换

## 🖼️ 效果展示

### ① 文档与解析

上传后逐路径解析状态（向量 / 图谱 / 百科三条腿；视频文档另有「语音 / 分镜 / 配文」三条预处理腿），失败可就地重试；点开文档即进入切片抽屉。

### ② 百科：生成条目 / 我的条目

AI 按实体资格自动沉淀「生成条目」；用户自建的「我的条目」与 AI 完全隔离、永不自动更新，可一键「混入搜索」参与检索；条目编辑内容还会作为后续重生成的「生成方向」。

### ③ 检索测试：三路命中对比

一条查询同时跑向量 / 图谱 / 百科三路，命中并列展示（含跨路耗时排名），结果可一键存为评测题。

### ④ 向量空间

切片 / 实体 / 百科 / 条目四类点的 2D / 3D 投影；检索命中实时叠加到图上。

### ⑤ 知识图谱

实体关系力导向图，社区层可上卷看全局；检索路径按种子 / 扩展 / 证据三层染色，叠加不重排布局。

### ⑥ 评测

题库（可由 AI 从文档生成候选、人工采纳）+ 指标总览 + 趋势图；运行中可见三阶段进度，支持中止。

### ⑦ 模型设置

聊天模型由 DSH 提供、自动同步；RAG 功能模型按角色分组（图谱抽取 / 评测裁判 / 说明生成 VLM / 百科生成 / 考题合成），嵌入、重排、解析与重建索引都在「功能模型设置」里完成。

```sh
# 发布后：GitHub 仓库地址（建议钉 tag 或 commit，不要跟 main）
dsh plugin --profile <name> add git+https://github.com/<owner>/dsh-harness-rag.git#<tag-or-commit>
```

三种方式装的是同一份插件代码，首次运行面完全一致。装完重启该 profile 的 DSH，打开右栏「知识库」tab：

1. **确认位置** — 默认 `<DSH_HOME>/harness-rag`（`DSH_HOME` 缺省 `~/.dsh`），可点「更改…」选父目录，实际根为 `<父目录>/harness-rag`。
2. **开始准备** — 下载运行时包（约 315 MB）并解压（约 840 MB），随后启动内置 Qdrant 与知识服务；首次约 1–2 分钟，之后启动为秒级。
3. **配置嵌入模型** — 就绪后顶部横幅提示；在「功能模型设置」里选嵌入模型即可上传文档。

平台：首期只提供 **Windows x64** 运行时包；其他平台安装后会在面板明确报「没有可用的运行时包」，此时改用外部服务（见操作手册）。

完整部署、运行根、外部模式、升级回滚、清理卸载与运行时包构建见 [插件操作手册](docs/plugin-manual.md)。
